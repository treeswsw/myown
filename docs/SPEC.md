# 갱식 클럽 — 개발 지시문 (SPEC)

친구끼리 각자 기기에서 동시에 즐기는 실시간 웹 카드 게임. 이 문서가 구현의 기준이다.
시각 기준은 `design/` 폴더의 시안 이미지와 `design/v3.html`(three.js 시안 원본)이다.

## 1. 범위

- 게임 모드 2개: **텍사스 홀덤**(2~6명), **블러핑 카드**(2~4명, 리볼버 벌칙).
- 같은 사이트의 다른 게임: **라이어게임**(3~8명, 18절), **요트다이스**(2~4명, 19절), **갱식마인드**(2~8명, 그림 맞히기, 20절).
- 독립 웹사이트. 서버가 모든 규칙을 판정하고, 각 플레이어에게는 그 사람이 볼 수 있는 정보만 보낸다.
- 아이디만으로 로그인(비밀번호 없음). 아이디별로 칩·전적·프로필 사진이 저장된다.
- PC 브라우저와 휴대폰 **가로 화면**. 세로로 들면 "화면을 가로로 돌려주세요" 안내만 띄운다.
- 실제 돈 기능 없음. 칩은 가상 칩이다.

## 2. 기술 구성

- Node.js 20+, ESM(`"type":"module"`), 패키지 하나(루트 `package.json`).
- 서버: Node `http` + `ws`. Express 등 프레임워크를 쓰지 않는다. `dist/` 정적 파일 제공 + `/ws` WebSocket.
- 저장소: `DATABASE_URL`이 있으면 PostgreSQL(`pg`), 없으면 메모리 저장(개발·테스트용). 같은 인터페이스(`server/store.js`).
- 클라이언트: Vite + three.js(0.160). 소스는 `client/`, 빌드 결과는 `dist/`.
- 테스트: `node --test` (`test/`).
- 스크립트: `npm run dev`(서버+Vite), `npm run build`, `npm start`(= `node server/index.js`), `npm test`.

```
shared/   cards.js handeval.js holdem.js bluff.js   순수 함수 게임 엔진 (DOM·네트워크 의존 없음)
server/   index.js rooms.js store.js protocol.js
client/   index.html src/ (main.js net.js scene/ ui/ anim/) public/assets/
test/     holdem.test.js bluff.test.js handeval.test.js rooms.test.js
design/   시안
```

## 3. 계정과 저장

- 아이디: 2~12자, 한글·영문·숫자·`_`. 앞뒤 공백 제거, 대소문자 구분 없음(소문자로 정규화해 키로 쓰고 표시용 원문은 따로 저장).
- 저장 항목: `id, name, bank(보유 칩), avatar(JPEG data URL 또는 null), stats{hands,wins,biggestWin,refills,bluffGames,bluffWins}`(라이어게임은 `stats.liar`, 갱식마인드는 `stats.draw = {games,wins,correct,points}`가 더해진다).
- 신규 아이디는 `bank = 10000`.
- 프로필 사진: 클라이언트가 정사각형으로 잘라 160×160 JPEG로 줄여 보낸다. 서버는 `data:image/jpeg;base64,` 접두사와 60KB 이하만 허용한다.
- 같은 아이디로 새 연결이 오면 이전 연결을 끊고 새 연결이 자리를 이어받는다.
- 클라이언트는 아이디를 `localStorage`에 저장해 다음 방문 때 자동 로그인한다.

## 4. 방

- 방 코드: 영문 대문자 4자(혼동되는 I, O 제외). 방은 메모리에만 존재하며, 사람이 없으면 60초 뒤 삭제한다.
- 방을 만든 사람이 방장. 방장이 나가면 남은 사람 중 가장 먼저 들어온 사람이 방장이 된다.
- 게임 시작과 모드 변경은 방장만, 판 사이(대기 상태)에만 가능하다.
- 정원을 넘으면 입장을 거절한다. 진행 중에 들어온 사람은 다음 판부터 참가한다(관전 상태).
- 접속이 끊기면 자리는 60초 유지한다. 그동안 차례가 오면 제한 시간 뒤 자동 행동한다. 60초가 지나면 방에서 내보낸다.

## 5. 텍사스 홀덤 규칙

- 노리밋. 블라인드 50/100 고정. 2명일 때는 딜러가 스몰 블라인드.
- **테이블 스택**: 자리에 앉을 때 `min(bank, 5000)`을 테이블로 가져온다(`bank`에서 차감). 방을 나가면 스택이 `bank`로 돌아간다.
- 진행: 프리플랍 → 플랍(3장) → 턴 → 리버 → 쇼다운. 일반적인 최소 레이즈 규칙(직전 레이즈 크기 이상). 스택이 부족한 올인 레이즈는 허용한다.
- 사이드 팟을 정확히 계산한다. 동점은 균등 분할, 나머지 칩은 딜러 왼쪽부터 준다.
- 한 명만 남으면 쇼다운 없이 그 사람이 팟을 가져가고 패는 공개하지 않는다.
- 올인으로 더 행동할 사람이 없으면 남은 공용 카드를 자동으로 끝까지 깐다.
- 차례당 30초. 넘기면 체크가 가능하면 체크, 아니면 폴드.
- 첫 판은 방장이 시작한다. 이후에는 결과 표시 뒤 자동으로 다음 판이 시작된다(승리 연출 약 6초 뒤). 칩이 있는 사람이 2명 미만이면 대기 상태로 돌아간다.
- **탈락**: 판이 끝났을 때 스택이 0인 사람은 탈락 연출 대상이다. 탈락자는 `bank`에 칩이 있으면 다음 판에 `min(bank,5000)`으로 다시 앉고, `bank`도 0이면 무료 리필 10,000을 받고(`stats.refills += 1`) 다시 앉는다.
- 전적: 판마다 참가자 `hands += 1`, 팟을 가져간 사람 `wins += 1`, `biggestWin` 갱신.

## 6. 블러핑 카드 규칙

- 2~4명. 칩을 걸지 않는다.
- 덱 20장: A 6장, K 6장, Q 6장, 조커 2장. 라운드마다 생존자에게 5장씩 나눠 준다.
- 라운드마다 "이번 카드"(A·K·Q 중 무작위)가 정해진다.
- 차례에는 손패 1~3장을 엎어 내며 "이번 카드"라고 주장한다. 조커는 어떤 카드로도 통한다.
- 다음 사람은 **LIAR**(직전에 낸 카드가 거짓이라고 지목)를 외치거나 자기 카드를 낸다.
  - 공개 결과 낸 카드가 전부 "이번 카드" 또는 조커면 지목한 사람이, 아니면 낸 사람이 벌칙을 받는다.
- 손패를 다 낸 사람은 그 라운드에서 건너뛴다. 카드를 가진 사람이 직전에 낸 사람 한 명뿐이면, 다음 생존자는 손패가 없어도 차례를 받고 반드시 LIAR를 외쳐야 한다.
- **리볼버 벌칙**: 각자 6칸 리볼버를 가진다. 게임 시작 때 서버가 플레이어마다 탄 위치(0~5)를 무작위로 정한다. n번째로 당겼을 때 `n-1 == 탄 위치`면 탈락, 아니면 생존하고 `shots`가 1 늘어난다. 첫 발에 탈락할 수도 있다. 탄 위치는 클라이언트에 절대 보내지 않는다.
- 벌칙 뒤 생존자가 2명 이상이면 새 라운드를 시작한다(새로 5장씩, 새 "이번 카드"). 벌칙을 받은 사람이 살아 있으면 그 사람부터, 아니면 그다음 생존자부터 시작한다.
- 생존자가 1명이 되면 그 사람이 우승이고 대기 상태로 돌아간다. 리볼버는 새 게임마다 초기화된다.
- 차례당 30초. 넘기면 손패가 있으면 첫 번째 카드 1장을 내고, 없으면 LIAR.
- 전적: 참가자 `bluffGames += 1`, 우승자 `bluffWins += 1`.

## 7. 통신 규약 (WebSocket `/ws`, JSON)

- 코인·뽑기·상점·비밀번호 메시지(`coin`, `pin`, `login`의 `pin/tok/newPin`, `reset`의 `pw`, `me.wallet`)는 22-10절.

모든 메시지는 `{t: 종류, ...}`. 서버는 형식이 잘못됐거나 지금 할 수 없는 요청을 무시하고 `{t:'error', msg}`를 보낸다. 연결당 초당 20개를 넘는 메시지는 버린다.

클라이언트 → 서버

| t | 필드 | 설명 |
|---|---|---|
| `login` | `id` | 로그인 또는 신규 생성 |
| `avatar` | `data` | 프로필 사진 등록 |
| `create` | `mode: 'holdem'\|'bluff'` | 방 만들기 |
| `join` | `code` | 방 입장 |
| `leave` | | 방 나가기 |
| `mode` | `mode` | 방장: 모드 변경 |
| `start` | | 방장: 게임 시작 |
| `act` | `a: 'fold'\|'check'\|'call'\|'raise'\|'allin'`, `amount?` | 홀덤 행동. `raise`의 `amount`는 이번 베팅 라운드에서 내 총 베팅액("raise to") |
| `play` | `cards: number[]` | 블러핑: 손패 인덱스 1~3개 |
| `liar` | | 블러핑: 거짓말 지목 |
| `emote` | `e: 0..5` | 이모티콘 |

서버 → 클라이언트

| t | 필드 | 설명 |
|---|---|---|
| `me` | `user{id,name,bank,avatar,stats}` | 로그인 결과, 변동 시 재전송 |
| `room` | `state` 또는 `null` | 방 상태 전체(개인별 시점). 변할 때마다 전송 |
| `event` | `e` | 연출용 이벤트(아래) |
| `error` | `msg` | 사용자에게 보여줄 한국어 메시지 |

`room.state` (개인별 시점)

```js
{
  code, mode, hostId, phase: 'lobby'|'playing'|'result',
  you: playerId,
  players: [{ id, name, avatar, seat, connected, spectating,
    // holdem
    stack, bet, folded, allin, isDealer, cards: null | [c,c],   // 남의 패는 쇼다운 공개 전까지 null
    // bluff
    alive, handCount, shots }],
  turn: playerId|null, turnEndsAt: epochMs|null,
  // holdem
  board: [c...], pot, pots: [{amount, eligible:[id]}], street: 0..3, toCall, minRaiseTo, maxRaiseTo,
  myCards: [c,c] | null, myBest: '트리플' 등 | null,
  result: null | { winners:[{id, amount, handName, cards:[c x5]}], shown:{[id]:[c,c]}, busted:[id] },
  // bluff
  tableRank: 'A'|'K'|'Q', round, myHand: ['A','K','J'...],   // 'J' = 조커
  lastPlay: null | { by, count },
  reveal: null | { by, caller, cards, lie, loser, dead, shots },
  winnerId
}
```

카드 표기: 홀덤은 `'As','Td','9h'`처럼 랭크(`23456789TJQKA`)+무늬(`shdc`) 문자열.

`event.e` 종류: `deal`, `blinds`, `action{id,a,amount}`, `street{street,cards}`, `allin{id}`, `showdown`, `win{...}`, `bust{id, by}`, `bluffDeal`, `bluffPlay{id,count}`, `liar{caller,by}`, `reveal{...}`, `shot{id,dead,shots}`, `bluffWin{id}`, `emote{id,e}`. 클라이언트는 이벤트로 연출을 재생하고, 화면의 진짜 상태는 항상 `room.state`를 따른다.

### 7-1. 라이어게임 (추가)

화면 → 서버
- `{t:'create', mode:'liar'}` — 라이어 방 만들기. `LIAR=off`면 `'라이어게임은 아직 열리지 않았습니다.'`
- `{t:'lg', a: 글자 1~20자, ...}` — 라이어 전용 요청 전부. 봉투만 protocol.js 가 보고 속은 방(`shared/liar/protocol.js`)이 검사한다.
  포커 방에서 보내면 `'알 수 없는 요청입니다.'`
- `{t:'lg', a:'rank'}` — 방 안팎 어디서나. 서버(hub)가 직접 `lgRank`로 답하고 방에 넘기지 않는다. `LIAR=off`면 거절.
- 라이어 방에서 `mode`·`act`·`play`·`liar`(블러핑) → `'지금은 할 수 없습니다.'` (오류로 죽지 않는다)
- 포커 방에서 `{t:'mode', mode:'liar'}` → `'라이어게임은 방을 새로 만들어 주세요.'`

서버 → 화면
- `{t:'me', user, liar:'off'|'test'|'on'}` — **`me`에 `liar` 칸 하나 추가**(새 메시지 종류 없음). 버튼 보이기 판단에 쓴다.
- `{t:'lgRank', top:[{name, score, games}], mine:{rank|null, score}}` — 누적 1점 이상 상위 20명. 사진 없음.
- `{t:'rooms', list}`의 항목에 `mode:'liar'`, `max:8`.
- `{t:'room', state}`에서 `state.mode==='liar'`이면 모양은 GDD 9-3(사진 없음). 알림 `event.e`는 GDD 9-4(`faces` 등).

버튼 보이기(화면): `보임 = liar==='on' || (liar==='test' && 주소에 ?liar=1)`. `test`는 "숨김"이지 "잠금"이 아니다(주소를 아는 사람은 만들 수 있다).

### 7-2. 갱식마인드 (추가)

자세한 모양·값·오류 글은 `docs/draw/GDD.md` 10절(`shared/draw/protocol.js`가 요청 속을 검사). 사이트 전체 통신에서 바뀌는 점만 적는다.

화면 → 서버
- `{t:'create', mode:'draw'}` — 갱식마인드 방 만들기. `DRAW=off`면 오류 `dr_off`(`'갱식마인드는 아직 열리지 않았습니다.'`)
- `{t:'dr', a: 글자 1~20자, ...}` — 갱식마인드 전용 요청 전부. 봉투만 hub 가 보고 속은 `shared/draw/protocol.js`가 검사한다.
  포커·라이어 방에서 보내면 `'알 수 없는 요청입니다.'`
- 갱식마인드 방에서 `mode`·`act`·`play`·`liar`·`lg`가 오면 오류 `dr_now`(`'지금은 할 수 없습니다.'`, 죽지 않는다)

서버 → 화면
- `{t:'me', user, liar, draw:'off'|'test'|'on'}` — **`me`에 `draw` 칸 하나 추가**(새 메시지 종류 없음). 로비 칸 보이기 판단에 쓴다.
- `{t:'rooms', list}`의 항목에 `mode:'draw'`, `max:8`, `phase:'lobby'|'playing'`(`lobby`·`final`이 아니면 `'playing'`).
- `{t:'error', msg, code}` — **`error`에 `code` 칸 추가**(갱식마인드 오류에만 있으면 된다. 기존 오류에는 없어도 된다). 화면 분기와 시험용.
- `{t:'room', state}`에서 `state.mode==='draw'`이면 모양은 GDD 10-4. 알림 `event.e`는 GDD 10-5.

로비 보이기(화면): `보임 = draw==='on' || (draw==='test' && 주소에 ?draw=1)`. `test`는 "숨김"이지 "잠금"이 아니다.

### 7-3. 공통 방 (2026-11-13, 묶음 2)
접두사 `<p>` = 그 게임의 오류 코드 앞 글자(`pk_ lg_ yt_ dr_ gk_ mn_`). 모든 방 오류는 `{t:'error', msg, code}`.

화면 → 서버
| t | 필드 | 누가·언제 | 오류 code |
|---|---|---|---|
| `create` | `mode`, `game?` | 로비 | `<p>off` |
| `start` | | 방장, `wait≠null` | `<p>host`, `<p>now`, canStart 의 코드 |
| `set` | `patch: {키: 값}` (스키마 키, 중첩은 객체 그대로 예: `{times:{speak:30}}`) | 방장, `wait≠null` | `<p>host`, `<p>now`, 게임 검사 코드 |
| `pick` | `patch: {키: 값}` (개인 칸: 갱스껄 `color`) | 본인, `wait≠null` | `<p>now`, 게임 검사 코드 |
| `kick` | `id` | 방장, `wait≠null`, 자기 아님 | `<p>host`, `<p>now`, `<p>bad` |
| `leave` `chat` `emote` `pemote` `snd*` | 그대로 | | |
| ~~`mode`~~ | | **없어짐**(방 안 홀덤↔블러핑 전환) | 한 배포 동안 받아서 `{msg:'방을 새로 만들어 주세요.', code:'pk_mode'}`, 묶음 3 청소 때 protocol 에서 삭제 |

서버 → 화면
- `room.state` 공통 칸(모든 게임, 게임 칸은 그 아래에 그대로):
```js
{ code, mode, hostId, you, now, phase,
  players: [{ id, name, connected, awayUntil, spectating, ...게임 칸 }],   // 사진 없음(포커는 이행 기간 avatar 유지, S3 때 뺌)
  wait: null | { can, why: null | {msg, code}, set: {...방 설정}, own: { [id]: {...개인 칸} },   // 대기·결과 동안만
                 result: null | {                                // 공통 결과(2026-11-14): 지난 판 ctx.finish, 다음 판 시작 때 null
                   rows: [{ id, name, rank, score?, note? }],     // 순위 순서. 이 판을 끝까지 한 사람(관전자·나간 사람 없음)
                   gain: { [id]: 정수 },                         // 이번 판 증감(코인: 지급 + add, 칩: 이번 게임 동안). 방 전원(관전자 포함)이 같은 값
                   unit: 'coin' | 'chip',                        // 홀덤만 'chip'
                   add?: { label, by: { [id]: 정수 } } } },       // gain 안에 든 지급 밖 증감(미니 베팅). 화면은 "판 코인 +a · 베팅 +b"
  specs: [{ id, name, connected }] }            // 관전 계정 자리(7-4). 참가자(players)와 따로, 최대 4
```
- 강퇴된 사람: `{t:'error', msg:'방장이 내보냈습니다.', code:'<p>kicked'}` 다음 `room:null`.
- `event.e`: `joined{id,name}` `left{id,name}` `away{id}` `back{id}` 를 **모든 게임**이 보낸다(포커 새로). `faces.items[]` 에 `look`(장착 아이템 `{title?, frame?, color?, …}`, 상점의 `g.equip` 그대로) 추가.
- 판 끝 코인은 `wait.result`(공통 결과 화면)로만 알린다. 옛 `{t:'coin', a:'got'}`·`{t:'coin', a:'stake'}` 알림은 없어졌다(2026-11-14). 공개된 결과만 싣는다(비밀 없음).
- `sndAdd` 로 방 소리가 넘쳐 지워지면 지워진 것마다 `sndDel{sid}` 가 뒤따른다.

호환·이행
- 옛 전용 요청은 그대로 받는다(같은 함수로 감): `lg settings/kick`, `dr settings/kick/lobby`, `gk color`, `mn game/again/start`. 화면이 새 메시지로 다 옮긴 뒤 묶음 3 청소에서 지운다.
- 옛 상태 칸(라이어 `settings`, 갱식마인드 `settings` 등)도 그대로 둔다. `wait.set` 은 대기실용 사본이다.
- 옮기기 전 게임은 옛 모양 그대로(공통 칸 없음). 화면 틀은 `client/src/games.js` 의 `mount` 가 있는 게임만 새 길로 그린다.

### 7-4. 관전 계정 (2026-11-13, 묶음 3)
- 아이디가 `관전` + 숫자(`관전1`, `관전2`, …)인 계정은 어느 방에서든 **관전자**다. 판별은 `shared/spectator.js` 한 곳(`isSpectatorId`, `SPEC_MAX = 4`). 로그인은 보통 계정과 같다.
- 입장은 `{t:'join', code}` 그대로. 대기 중이든 게임 중이든 들어오고, `room.state.specs` 에만 들어간다(`players`·자리·차례·정원·시작 인원·방장 밖). 관전 자리가 차면 `{code:'<p>specfull', msg:'관전 자리가 가득 찼습니다.'}`, 참가자가 없는 방은 `<p>bad`.
- 만들기 `{t:'create'}` 는 `{code:'spec_create', msg:'관전 계정은 방을 만들 수 없습니다. …'}`.
- 관전자가 보낼 수 있는 것: `leave` `chat` `emote` `pemote` `snd*`. 게임 요청(`act` `play` `liar` `lg` `yt` `dr` `gk` `mn`)·`pick` 은 `{code:'<p>spec', msg:'관전 중에는 할 수 없습니다.'}`(게임에 넘기지 않음), `start` `set` `kick` 은 `<p>host`.
- 채팅·이모티콘은 그 게임의 규칙 훅(`chatCheck`·`mediaBlocked`)을 자리 없는 사람으로 그대로 탄다(라이어: 판 중 글 금지·기본 이모티콘만). 채팅을 게임이 맡는 갱식마인드(`chatOwn`)는 게임 중(고르기·그리기·공개) 관전자 채팅을 `<p>spec`("게임 중에는 관전자가 채팅할 수 없습니다.")으로 막는다: 정답 판정에 끼지 않고, 정답을 아는 사람과 말이 오가는 길이 없다. 대기·최종 결과 중에는 보통 채팅. 관전자 이모티콘·소리는 갱식마인드에서 늘 된다(단어를 모른다).
- 관전자 기기에는 비밀이 없다: 각 게임 view 의 "자리 없는 사람" 시점(라이어 `my:{word:null, role:null}`, 갱식마인드 `word:null, choices:null`·정답자끼리 글 없음, 갱스껄 `mine:null`, 포커 `myCards:null`·남의 `cards:null`, 블러핑 `myHand:[]`). 게임 알림은 방 전체 알림만(갱식마인드는 "못 맞힌 사람"이 받는 것: 그림 선·`drNew`·`drHit`·공개 글).
- 방장은 관전자를 대기 중이든 게임 중이든 내보낼 수 있다(`{t:'kick', id}`, 대기실 관전 줄의 ×).
- 판 코인은 받지 않는다(Shell `ctx.finish` 가 참가자만 남긴다). 끊기면 60초 유예 뒤 나간다.
- 빈 방은 참가자 기준: 마지막 참가자가 나가면 남은 관전자에게 `{t:'error', code:'<p>closed', msg:'참가자가 모두 나가 방이 닫혔습니다.'}` 다음 `room:null`.
- `event.e` `joined`·`left` 에 관전자면 `spec: true`. 방 목록 `count` 는 참가자만.
- 화면: 게임 중 위 가운데 "관전 중"(`.rm-spec`). 조작 버튼은 게임이 "내 자리 없음"으로 그리지 않는다. 갱식마인드는 게임 중 관전자 채팅 줄을 잠근다.

## 9. 모션

모든 연출은 `prefers-reduced-motion`에서 짧은 전환으로 대체한다. 연출 중에도 입력은 막지 않는다(단, 내 차례 휠은 연출이 끝난 뒤 뜬다).

- 카드 배분: 딜러 자리에서 각 자리로 한 장씩 날아간다.
- 베팅: 칩이 자리 앞 더미에서 베팅 위치로 미끄러진다. 베팅 라운드가 끝나면 모든 베팅 칩이 팟으로 모인다.
- 공용 카드: 뒤집히며 공개되고, 왼쪽 아래 빈칸에도 뒤집히며 채워진다.
- 행동 표시: 핀 아이콘과 금액이 튀어 오르듯 나타난다.
- **올인**(약 2.5초): 프로필 사진 아래로 몸통과 팔다리가 자라난다 → 팔을 뒤로 젖힌다 → 자기 칩 더미를 중앙으로 밀어버린다(칩이 무너지며 미끄러짐, 화면 흔들림, "ALL IN") → 몸이 사진 속으로 들어간다.
- **승리**(약 6초): 족보 이름이 크게 뜨고 승자의 최고 5장이 가운데 펼쳐진다. 그 아래 가운데에 승자 프로필과 획득 금액. 이어서 **팟의 칩이 승자 자리로 날아가 더미에 합쳐지고** 스택 숫자가 올라간다.
- **포커 탈락**(약 3초): 그 판 승자의 프로필에서 몸과 팔이 자라나 권총을 겨눈다 → 발사(섬광, 화면 흔들림) → 탈락자 프로필이 동전처럼 뒤집히며 흑백이 된다 → 승자가 총구 연기를 불고 몸이 들어간다.
- **리볼버 벌칙**(약 3초): 벌칙 대상의 프로필에서 몸과 팔이 자라나 자기 리볼버를 든다 → 탄창 회전, 카메라가 당겨지고 느려짐 → 빈 칸이면 "철컥", 안도, 숫자 증가 / 탄이면 섬광, 프로필이 뒤집히며 흑백으로 탈락.
- **몸 스타일**: 만화풍이 아니라 **현실적이고 기괴한** 느낌. 정장을 입은 사실적인 비율의 마네킹 몸(어깨·팔꿈치·손목 관절이 있는 길쭉한 팔, 손가락이 있는 손, 다리)이고 머리 자리에는 납작한 프로필 사진이 그대로 붙는다. three.js 기본 도형(캡슐 등)과 관절 계층으로 만들고, 가속·감속과 약간의 지연 동작으로 부드럽게 움직인다. 피·상처 표현은 넣지 않는다.
- 효과음: Web Audio로 합성(카드, 칩, 철컥, 총성, 승리). 소리 버튼으로 끌 수 있고 설정은 저장한다.

## 10. 품질 기준

- 서버가 유일한 판정자다. 클라이언트가 보낸 값은 전부 검증한다(차례, 금액 범위, 인덱스, 형식).
- 남의 패, 덱, 탄 위치는 어떤 메시지로도 새지 않는다. 이를 확인하는 테스트를 둔다.
- 엔진은 순수 함수로 작성하고, 무작위는 주입 가능한 `rng`로 받아 테스트에서 재현할 수 있게 한다.
- 테스트: 족보 판정, 사이드 팟, 최소 레이즈, 올인 자동 진행, 칩 총량 보존(무작위 수천 판), 블러핑 진행과 리볼버, 시점별 정보 누출 없음.
- 이름 등 사용자 입력은 `textContent`로만 화면에 넣는다. `innerHTML`에 사용자 입력을 넣지 않는다.
- 불필요한 추상화, 죽은 코드, 쓰지 않는 의존성을 두지 않는다. 주석은 "왜"가 필요한 곳에만.
- 휴대폰(가로)에서 초당 30프레임 이상을 목표로 한다. 픽셀 비율 상한 2, 그림자 해상도와 후처리를 기기 성능에 따라 낮춘다.

## 11. 배포

- Render 웹 서비스 1개. 빌드 `npm ci && npm run build`, 시작 `npm start`, 환경 변수 `DATABASE_URL`(Neon). `render.yaml`과 `README.md`에 절차를 적는다.
- 서버는 `PORT` 환경 변수를 따른다. `/healthz`는 200을 돌려준다.
- 시작할 때 테이블이 없으면 만든다(`users` 테이블 하나).

## 12. 채팅

- 방 안의 모든 사람(관전자 포함)이 대기 화면과 게임 중에 글자 채팅을 할 수 있다.
- 규약: 클라이언트 → 서버 `{t:'chat', text}`. 서버는 앞뒤 공백과 제어 문자를 제거하고 1~120자만 받는다. 한 연결당 1초에 1개, 10초에 5개까지만 받고 넘으면 `error`("채팅을 너무 빨리 보내고 있습니다")로 답한다.
- 서버 → 방 전체: `{t:'event', e:{k:'chat', id, name, text, ts}}`. 방은 최근 30개를 기억하고, 입장·재접속한 사람에게 `{t:'event', e:{k:'chatLog', items:[{id,name,text,ts}...]}}`를 한 번 보낸다. 방이 사라지면 기록도 사라진다(저장하지 않는다). 채팅은 게임 상태와 차례 타이머에 영향을 주지 않는다.
- 화면
  - **오른쪽 위에 채팅 아이콘**(흰 테두리 원형, 말풍선 그림)을 둔다. 방 코드·모드 글자 바로 아래. 읽지 않은 메시지가 있으면 작은 노란 점이 붙는다.
  - 아이콘을 누르면(PC에서는 Enter로도) 입력창이 열린다. 유리 느낌의 한 줄 막대, 120자 제한. Enter 또는 보내기 버튼으로 전송, Esc나 바깥을 누르면 닫힌다. 휴대폰에서는 키보드에 가리지 않게 화면 위쪽에 뜬다. 입력창이 열려 있어도 내 차례 조작은 막지 않는다. 한글 조합 중 Enter로는 전송하지 않는다.
  - 채팅을 보내면 **보낸 사람의 프로필 사진 위에 말풍선**이 뜬다(행동 핀 아이콘이 있으면 그 위). 살짝 튀어 오르며 나타나고, 약 4초 뒤 **위로 천천히 떠오르며 흐려져 사라진다**. 같은 사람이 새로 치면 이전 말풍선은 위로 밀려 올라가며 사라지고 새 말풍선이 그 자리에 뜬다. 긴 글은 두 줄까지 보이고 나머지는 …로 줄인다. 내 말풍선도 내 프로필 위에 똑같이 뜬다.
  - 말풍선은 3D 장면 위에 떠 있을 뿐 조작을 가리지 않는다(누를 수 없음).
  - 입력창 옆 "기록" 버튼으로 최근 30개 목록(이름, 시간, 내용)을 볼 수 있다.
  - 대기 화면(방 대기)에서는 프로필이 화면에 없으므로, 패널 아래에 최근 메시지 몇 줄과 입력창을 보여준다.
- 모든 채팅 글자는 `textContent`로만 넣는다. 링크로 만들지 않는다.
- **강조 채팅**: 글 맨 앞에 `#`을 붙여 보내면(예: `#올인간다`) `#`은 보이지 않고 말풍선이 대폭 크게(글자 크기 약 2.5배, 굵게) 뜬다. 더 크게 튀어 오르며 나타나고 살짝 흔들린 뒤 일반 말풍선과 같은 방식으로 위로 사라진다(머무는 시간 약 5초). `#`만 보내거나 `#` 뒤가 공백뿐이면 보내지 않는다. 서버는 글을 그대로 전달하고, 강조 여부는 화면에서 맨 앞 `#`로 판단한다. 기록 목록에서도 강조 글은 굵게 표시한다.
- **크기 표시 단계(2026-11-13 변경, 네 게임 공통)**: `*` = 1단계: 보통 글자의 2배(휴대폰 가로 1.7배), 노란색(#ffd60a) 굵은 글씨. `#`·`**` = 2단계: 그대로(빨강, 3배). `***` = 3단계: 크기는 그대로(4.8배)이고, 글자마다 글꼴(구글 한글 글꼴 16종)·무지개 일곱 색·기울기·크기·움직임(떨림, 통통 튀기, 커졌다 작아지기, 흔들흔들, 깜빡임, 지지직)이 랜덤이다. 바로 옆 글자와는 색·글꼴이 겹치지 않는다. 랜덤은 보낸 사람·시각·글로 정해져 방 안 모두가 같은 모양을 본다. 3단계 글꼴은 처음 3단계 말풍선이 뜰 때 불러온다. 움직임 줄이기 설정이면 글자 움직임은 끈다. 기호 종류는 바꾸지 않는다(라이어의 기호 떼기와 맞춤).

## 13. 실제 플레이 후 변경 (우선 적용, 위 내용과 다르면 이 절이 우선)

- **차례 제한 시간 없음**: 접속 중인 사람의 차례에는 시간제한과 자동 행동이 없다. `turnEndsAt`은 항상 `null`이고 타이머 링도 그리지 않는다. 단, 차례인 사람의 **접속이 끊긴 경우에만** 유예 60초 뒤 자동 행동(체크 가능하면 체크, 아니면 폴드 / 블러핑은 기존 규칙)을 하고 방에서 내보낸다. 접속이 끊긴 사람에게 차례가 오면 같은 유예를 적용한다.
- **방 목록으로 입장**: 방 코드를 입력하지 않는다. 로그인한 사람(방 밖)은 열려 있는 방 목록을 실시간으로 받는다. 방을 누르면 바로 참가한다.
  - 규약: 서버 → 방 밖에 있는 로그인 사용자에게 `{t:'rooms', list:[{code, mode, hostName, count, max, phase}]}`를 로그인 직후와 목록이 바뀔 때마다 보낸다(방 생성·삭제, 인원·모드·단계 변화). 변화가 잦으면 0.5초에 한 번으로 묶는다. 방을 나오면 다시 받는다.
  - 입장은 기존 `{t:'join', code}`를 그대로 쓴다(목록의 code 사용). 진행 중인 방에 들어가면 관전 후 다음 판부터 참가한다. 정원이 찬 방은 목록에 "가득 참"으로 보이고 누를 수 없다.
  - 로비 화면: 오른쪽 패널을 "새 게임"(모드 선택 + 방 만들기)과 "열린 방"(목록: 모드, 방장 이름, 인원 n/최대, 대기 중/게임 중) 으로 구성한다. 방이 없으면 "열린 방이 없습니다. 새 게임을 만들어 보세요." 코드 입력 칸은 없앤다. 대기 화면의 방 코드 표시와 복사 버튼도 없애고 방 제목은 "방장이름의 방"으로 보여준다. 게임 화면 오른쪽 위의 코드 글자도 모드 설명만 남긴다.
- **이모티콘**: 채팅처럼 보낸 사람의 프로필 위에 크게 떠서, 잠시 머문 뒤 위로 떠오르며 사라진다.
- **모든 조작은 마우스·터치(휴대폰, 태블릿)·펜에서 똑같이 동작해야 한다.** 누를 수 있는 요소는 최소 44px 크기의 터치 영역을 가진다.

## 14. 실제 플레이 후 변경 2 (위 내용과 다르면 이 절이 우선)

- **칩은 전부 테이블에 올린다**: 은행(bank)과 테이블 스택을 나누지 않는다. 홀덤 방에 앉으면 가진 칩 전부가 스택이다(신규 아이디 10,000). 방을 나가면 남은 스택이 그대로 계정 칩이 된다. "입장 시 최대 5,000" 규칙과 무료 리필은 없앤다.
- **탈락**: 판이 끝났을 때 스택이 0인 사람은 탈락이다. 탈락 연출 뒤 그 방에서 관전자가 되며(프로필 흑백, "탈락" 표시), 이후 판에 참가하지 못한다. 계정 칩도 0이 되고, 칩이 0인 아이디는 홀덤 방에 앉을 수 없다(관전만 가능, 방 만들기 불가: "칩이 없습니다. 새 아이디로 다시 시작하세요"). 다시 하려면 로그아웃해 새 아이디를 만들어야 한다. 블러핑 카드는 칩을 쓰지 않으므로 칩 0인 아이디도 할 수 있다.
- **방의 승부**: 칩을 가진 사람이 1명만 남으면 그 사람이 최종 승자다(`event` `k:'champion', id`). 방은 대기 상태로 돌아가고, 칩 가진 사람이 2명 이상 모여야 다시 시작할 수 있다.
- **난입**: 진행 중인 방에 들어오면 이번 판은 관전하고 다음 판부터 자동으로 참가한다(칩이 있을 때).
- **중간 퇴장 = 폴드**: 판 도중에 나가거나(나가기) 접속이 끊겨 유예가 지나면 그 판은 폴드로 처리한다. 이미 낸 칩은 팟에 남는다. 블러핑에서는 탈락으로 처리한다.
- **승자 발표를 분명하게**: 쇼다운에서 (1) 남은 사람들의 패를 모두 공개하고 (2) 승자의 프로필과 이름을 크게 강조하며 승자가 **자리에서 일어난다**(몸 연출), (3) 승자의 최고 5장을 이루는 카드(내 패 + 공용 카드)에 금색 테두리 하이라이트를 주고 나머지 카드는 어둡게 한다, (4) 족보 이름과 "○○ 승리 +금액"을 표시한 뒤 (5) 팟이 승자 자리로 이동한다. 패배한 사람들의 프로필은 어둡게 한다. 동점이면 승자 전원을 강조한다. 결과 상태에 `result.winners[].cards`(최고 5장)가 있으므로 이를 쓴다.
- 베팅 방식은 지금처럼 **노리밋**이다(최소 레이즈는 직전 레이즈 크기 이상, 최대는 자기 스택 전부).
- **카드 연출 속도**: 카드를 나눠 주는 연출, 공용 카드를 한 장씩 까는 연출, 카드가 뒤집혀 공개되는 연출(쇼다운, 왼쪽 아래 공용 카드 칸, 블러핑 공개 포함)을 지금보다 살짝 느리게 한다. 기준: 각 동작 시간과 카드 사이 간격을 약 1.4배로. 서버의 장면 대기 시간도 여기에 맞춘다(플랍·턴·리버를 연달아 깔 때 한 장면당 대기).

## 15. 쇼다운과 승리 연출 (14절의 "승자 발표" 항목을 대체)

천천히, 여운이 남게 진행한다. 전체 약 10초.

1. **패 공개 (약 2.5초)**: 베팅이 끝나 쇼다운이 되면, 남은 사람들의 패 2장이 **각자의 프로필 위에** 크게 떠서 한 사람씩 차례로 뒤집힌다(딜러 왼쪽부터, 사람 사이 약 0.6초). 모든 사람이 볼 수 있다. 폴드한 사람은 공개하지 않는다.
2. **승자 클로즈업 (약 1.2초)**: 카메라가 승자 쪽으로 천천히 당겨지고, 다른 사람들과 배경은 어두워진다. 승자가 자리에서 일어난다(`special.playStand`).
3. **승리 패 정리 (약 4초 유지)**: 화면 가운데에 한 줄로 **왼쪽에 승자의 손패 2장, 간격을 두고 오른쪽에 공용 카드 5장**을 크게 보여준다. 족보를 이루는 유효 5장은 위로 살짝 올라오며 금색 테두리로 밝게, 나머지 2장은 아래로 내려가고 어둡게(채도·밝기 낮춤) 한다. 유효 카드는 한 장씩 차례로 올라온다(장당 약 0.25초). 카드 줄 위에는 족보 이름을 크게, 아래에는 "이름 WINS +금액"을 표시한다. 승자 프로필은 카드 줄 옆에 함께 보인다.
4. **팟 이동 (약 1.5초)**: 팟의 칩이 승자 자리로 이동하고 스택 숫자가 올라간다. 카메라가 원래 위치로 돌아온다.
- 동점이면 승자를 차례로(각 약 2.5초) 보여준다. 쇼다운 없이 이긴 경우(모두 폴드)는 1·3단계 없이 승자 강조와 "이름 WINS +금액", 팟 이동만 한다(약 3초).
- 저사양(줄인 연출) 모드에서도 3단계의 카드 정리와 하이라이트는 반드시 보여준다(카메라 이동과 몸 연출만 생략).
- 서버의 결과 표시 시간은 쇼다운이 있으면 약 11초, 없으면 약 4초로 한다(탈락 연출이 있으면 기존대로 추가).

## 16. 사진 이모티콘과 사운드 (추가)

왼쪽 위 이모티콘 버튼을 누르면 열리는 패널에 탭 두 개를 둔다: **이모티콘 / 사운드**.

**이모티콘 탭**
- 기본 이모티콘 6종(기존).
- **사진 이모티콘**: "사진" 버튼으로 사진을 고르면 그 사진이 1회용 이모티콘으로 내 프로필 위에 크게(둥근 모서리 사각형, 약 120px) 떠서 약 3초 머문 뒤 위로 사라진다. 모두에게 보인다. 저장하지 않는다(보낼 때마다 다시 고른다. 최근에 보낸 사진 4장은 내 기기에만 기억해 다시 누를 수 있다).
- 클라이언트가 256×256 이내 JPEG로 줄여 보낸다(데이터 URL 40KB 이하).
- 규약: `{t:'pemote', data}` → 방 전체에 `{k:'pemote', id, data}`. 서버는 형식(JPEG 데이터 URL)과 크기를 검사하고, 아이디당 3초에 1개로 제한한다. 서버에 저장하지 않는다.

**사운드 탭**
- 기본 효과음 버튼 몇 개(합성음: 박수, 웃음 느낌의 삑, 실패음, 드럼 롤 등 4~6개).
- **내 사운드 추가**: "추가" 버튼으로 소리 파일을 고르고 이름(8자 이내)을 붙이면 버튼이 생긴다. 버튼을 누르면 방의 모든 사람에게 그 소리가 재생되고, 누른 사람 프로필 위에 스피커 아이콘과 사운드 이름이 잠깐 뜬다.
- 소리는 5초 이내, 200KB 이내로 클라이언트가 잘라서/줄여서 보낸다(초과하면 앞 5초만 쓰고 용량을 낮춰 다시 인코딩한다. 그래도 넘으면 "소리가 너무 큽니다" 안내).
- 내가 추가한 사운드는 내 기기에 저장되어(IndexedDB) 다음에도 버튼이 남고, 길게 눌러 삭제할 수 있다. 한 사람당 최대 8개.
- 규약: 처음 재생할 때 소리를 방에 올린다 `{t:'sndAdd', sid, name, data}` → 방 전체에 `{k:'sndAdd', sid, by, name, data}`(방은 메모리에 최대 24개 보관, 방이 사라지면 삭제). 재생은 `{t:'snd', sid}` → `{k:'snd', id, sid}`. 나중에 들어온 사람은 입장 시 `{k:'sndList', items:[{sid, by, name, data}]}`를 받는다. 기본 효과음은 `sid`가 `builtin:<이름>`이고 데이터를 보내지 않는다.
- 제한: 재생은 아이디당 2초에 1개, 올리기는 아이디당 10초에 1개. 서버는 데이터 URL 형식(audio/*)과 크기만 검사한다.
- 왼쪽 위 소리 버튼으로 음소거하면 이 사운드들도 들리지 않는다. 사운드 탭에 "다른 사람 사운드 끄기" 스위치도 둔다.
- 사진과 사운드는 연출 대기열과 뒤처짐 방지를 거치지 않고 바로 표시·재생한다. 이름 등 글자는 `textContent`로만 넣는다.
- **사운드는 방 전체가 공유한다(16절 보완)**: 누군가 사운드를 추가하면 방의 모든 사람의 사운드 탭에 버튼으로 나타나고, 누구나 눌러 재생할 수 있다(버튼에 추가한 사람 이름을 작게 표시). 사운드를 추가하면 재생을 기다리지 않고 **즉시 방에 올린다**. 방에 새로 들어온 사람도 기존 사운드 버튼을 모두 본다. 내가 추가한 사운드는 내 기기에도 저장되어, 다른 방에 들어가면 자동으로 다시 올라간다(10초에 1개 제한에 맞춰 차례로).
- **사운드 편집**: 사운드 탭에 "편집" 버튼을 둔다. 편집 모드에서는 각 사용자 추가 사운드에 미리듣기(나만 들림), 이름 바꾸기, 삭제가 나온다. 수정·삭제는 **추가한 사람과 방장**만 할 수 있다(다른 사람 것은 미리듣기만). 기본 효과음은 편집할 수 없다. 길게 눌러 삭제하는 방식은 없앤다.
  - 규약: `{t:'sndDel', sid}` → `{k:'sndDel', sid}`, `{t:'sndRename', sid, name}` → `{k:'sndRename', sid, name}`. 권한이 없으면 `error`. 아이디당 1초에 2개 제한.

### 19-1. 스위치

환경 변수 `YACHT`: `off`(화면·서버에 흔적 없음) / `test`(주소에 `?yacht=1`이 있을 때만 로비에 버튼) / `on`(모두에게).
값이 없거나 그 밖의 값이면 `on`(`LIAR` 도 같은 방식). `render.yaml` 은 `on`. `LIAR` 와 서로 영향을 주지 않는다.
화면: `보임 = yacht==='on' || (yacht==='test' && 주소에 ?yacht=1)`. `test`는 숨김이지 잠금이 아니다.

### 19-3. 서버 → 화면

- `{t:'me', user, liar, yacht:'off'|'test'|'on'}` — `me`에 `yacht` 칸 하나 추가. `user.stats.yacht` 는 한 판이라도 끝낸 뒤에 생긴다(없으면 0으로 본다).
- `{t:'rooms', list}` 항목에 `mode:'yacht'`, `max:4`, `phase:'lobby'|'playing'|'result'`.
- `{t:'room', state}` — `state.mode==='yacht'`이면 아래 모양. 프로필 사진은 없다(`faces` 알림).

```js
{
  code, mode: 'yacht', hostId, you,
  now,                                   // 서버 시각(ms)
  phase: 'lobby' | 'playing' | 'result',
  gameNo,                                // 이 방의 몇 번째 판(시작 전 0)
  players: [{ id, name, connected, awayUntil: epochMs | null, spectating }],   // 방에 있는 사람 전부(들어온 순서). awayUntil = 끊김 유예 끝(= 기권 시각)
  cols: [{ id, name, left,               // 점수표의 줄. playing·result: 이 판 참가자(차례 순서, 기권자 포함 left:true = "기권")
           scores: { ones: n | null, ... 12칸 },   //   lobby: 접속 중인 사람들의 빈 줄(들어온 순서)
           upper, bonus: 0 | 35, total }],
  round, rounds: 12,                     // round: 1..12 (lobby 0, result 12)
  turn: id | null,                       // 차례 시간 제한 없음(turnEndsAt 없음)
  waiting: id | null,                    // 차례인 사람이 끊겨 기다리는 중이면 그 사람 id(= turn). 기권 시각은 players[].awayUntil
  rollsLeft: 0..3,                       // 차례 시작 3
  rollNo,                                // 이 판에서 지금까지 굴린 횟수(연출 중복 방지용)
  shaking: bool,                         // 차례인 사람이 컵을 흔드는 중
  dice: null | [{ v: 1..6,               // null = 이번 차례에 아직 안 굴림(5개 모두 컵 안)
                  slot: null | 0..4,     // 보관 칸 번호(왼쪽부터). null = 트레이에 있음
                  x, z, yaw }],          // 트레이에서 멈춘 자리(GDD 4절 좌표, 소수 3자리). 보관 중이면 마지막 자리
  preview: null | { 칸: 점수 },           // 차례인 사람에게만: 그 사람의 빈칸마다 지금 주사위로 받을 점수. 그 밖에는 null
  pick: null | 칸,                        // 차례인 사람이 선택해 둔 칸. 모두에게 보낸다. 굴림·보관·차례 끝에 null
  last: null | { id, cat, score },       // 가장 최근 기록(강조 표시용). 판이 시작되면 null
  result: null | { reason: 'done' | 'alone',              // alone = 기권으로 1명(또는 0명) 남음
                   ranks: [{ id, name, total, rank }],   // 기권자 제외, 합계 큰 순. 동점은 같은 rank. 0명이면 []
                   winners: [id] },
}
```

- `preview` 말고는 모든 사람이 같은 값을 받는다(`you` 제외).
- `event.e` (요트 방)

| k | 필드 | 언제 |
|---|---|---|
| `faces` | `items: [{id, avatar}]` | 입장·재접속 때 전원 것, 누가 들어오거나 사진을 바꾸면 그 사람 것(라이어와 같은 모양) |
| `chat` `chatLog` `emote` `pemote` `snd` `sndAdd` `sndDel` `sndRename` `sndList` | 사이트 공통 | `chatLog` 는 최근 30개 |
| `joined` / `left` | `id, name` | 들어옴 / 나감(기권 포함) |
| `away` / `back` | `id` | 끊김 / 돌아옴(사이트 공통 모양 그대로). 끊긴 사람이 차례면 서버는 흔들기를 끝내고(`ytShake on:false`) `waiting` 을 채운 상태를 보낸다. 돌아오면 `waiting: null` 로 그대로 이어서 |
| `ytStart` | `gameNo, order: [id]` | 판 시작 |
| `ytTurn` | `id, round` | 차례 시작 |
| `ytShake` | `id, on` | 컵 흔들기 시작/끝 |
| `ytRoll` | `id, seed, thrown: [i], dice: [{v, slot, x, z, yaw} ×5], rollsLeft, rollNo, combo` | 굴림. `seed`: 0..2³²−1 정수, `thrown`: 이번에 굴린 주사위 번호(오름차순), `dice`: 굴린 뒤 상태, `combo`: `null`\|`'yacht'`\|`'largeStraight'`\|`'fourKind'`\|`'fullHouse'`\|`'smallStraight'`. 서버가 대신 굴리는 일은 없다(`auto` 없음) |
| `ytKeep` | `id, i, on, slot \| null, x, z, yaw` | 보관(`slot` = 들어간 칸) / 빼기(`x,z,yaw` = 돌아간 자리) |
| `ytPick` | `id, cat \| null` | 칸 선택이 생기거나 옮겨 가거나 풀림(굴림·보관으로 풀릴 때도 보낸다) |
| `ytScore` | `id, cat, score, bonus, total` | 기록. `bonus`: 이 기록으로 보너스 35를 새로 받았는가 |
| `ytDrop` | `id, reason: 'away' \| 'leave'` | 판 진행 중 참가자 기권(`away` = 끊긴 지 60초, `leave` = 나가기). 그 사람 차례였으면 이어서 `ytPick{cat:null}`·`ytTurn`(또는 `ytEnd`) |
| `ytEnd` | `reason, ranks, winners` | 판 끝(`result` 와 같은 값) |

- 화면은 `ytRoll` 의 `seed`·`thrown` 으로 `shared/yacht/sim.js` 를 돌려 움직임을 재생하고, 끝은 `dice` 의 자리와 눈으로 맞춘다. 눈은 서버 값만 쓴다.
- 화면은 세로일 때 사이트 `#rotate` 안내를 그대로 둔다(요트 전용 세로 배치 없음). 높이 720 미만은 점수표 두 덩어리(GDD 2-1).
- 시간 관련 환경 변수는 사이트 공통 `GRACE_MS` 하나뿐이다(`YT_TURN_MS`·`YT_AWAY_MS`·`YT_AUTO_SHOW_MS` 는 없다).
- 시험: `npm run check`(로비 요트 칸·방·컵·보관·두 번 눌러 기록·세로 안내 포함), `npm test`(+ `test/yacht/`, `test/ui/yacht-round.mjs` 한 판). 3D 모양·연출·소리·iPad/Safari 는 실기기 확인이 필요하다.

- 같은 아이디·프로필 사진·로비를 쓴다. 로비의 "새 게임"에 마지막(라이어게임·요트다이스 다음) 선택으로 "갱식마인드"(`2~8명 · 그림 보고 단어 맞히기`). `DRAW` 환경 변수가 `off`면 화면·서버 모두 없던 때와 같고, `test`는 주소에 `?draw=1`이 있을 때만 보이며, `on`은 모두에게 보인다. 기본 on(끄려면 `DRAW=off`; 값이 없을 때도 `on`, `render.yaml` 도 `on`). 3D 장면은 쓰지 않는다.
- 통신은 GDD 10절(`{t:'dr', a, ...}` 한 봉투, 모양 검사는 `shared/draw/protocol.js`). 정답 단어는 그리는 사람과 이미 맞힌 사람에게만 보내고, 시간·정답 판정은 서버가 한다.
- 누적 점수는 `users.stats.draw`(새 표 없음). 단어는 `server/liar/words.json`을 읽기만 한다.
- 시험: `npm test`(+ `test/draw/`, 한 판 `test/ui/draw-round.mjs`). 선 느낌·펜슬·손바닥·키보드·소리·모션·iPad/Safari 는 실기기 확인이 필요하다.

## 21. 관리자 모드 (2026-11-13 사용자 요청)

목표: 혼자서도 모든 게임(포커·블러핑·라이어·요트·갱식마인드, 앞으로 만들 게임 포함)의 진행과 연출을 시험한다.

### 21-1. 로그인
- 아이디 `관리자`는 예약 계정이다. `{t:'login', id:'관리자', pw}` 로만 들어간다. 비밀번호는 환경 변수 `ADMIN_KEY`, 없으면 `9975`.
- 틀리거나 없으면 로그인시키지 않고 `{t:'error', code:'adm_pw', msg:'관리자 비밀번호가 틀렸습니다.'}`.
  서버 전체에서 10분 안에 5번 틀리면 10분 동안 관리자 로그인을 막는다: `{t:'error', code:'adm_lock', msg:'잠시 후 다시 시도하세요.'}` (맞는 비밀번호도 거절).
- 그 밖에는 보통 계정과 같다(칩·전적·사진 저장). 단, 공개 랭킹(라이어 전체 랭킹)에는 나오지 않고 관리자 자신의 순위는 "없음"이다(2026-11-13 사용자 요청). 관리자에게만 `me` 메시지 맨 위에 `admin: true` 가 붙는다(`{t:'me', user, ..., admin:true}`, user 안이 아님)(다른 사람에게는 이 칸이 없다).
- 로그인 화면: 아이디 칸이 정확히 `관리자`이면 비밀번호 칸(숫자 키패드, 가림 글자)이 나타난다. 맞으면 비밀번호를 이 기기에 기억해 다시 연결할 때 함께 보낸다. `adm_pw` 를 받으면 기억한 비밀번호를 지우고 로그인 화면에 문구를 보인다.

### 21-2. 관리자 요청 `{t:'adm', a}`
| a | 하는 일 |
|---|---|
| `bot+` | 지금 방에 봇 한 명을 넣는다 |
| `bot-` | 가장 늦게 들어온 봇 한 명을 내보낸다 |
| `skip` | 지금 단계의 남은 시간을 0으로 만든다(다음 단계로) |
| `econ` `econSet` `econReset` | 세부 설정(21-7) |

- 성공하면 `{t:'admOk', a, bots}`(bots = 그 방의 봇 수). 실패는 `error`:
  관리자가 아님 `adm_no` "관리자만 할 수 있습니다." / 방에 없음 `adm_room` "방에 들어가서 쓰세요." /
  방에 관리자 말고 다른 사람이 있음 `adm_people` "다른 사람이 있는 방에서는 쓸 수 없습니다." /
  봇이 없음 `adm_nobot` "내보낼 봇이 없습니다." / 건너뛸 것이 없음 `adm_noskip` "건너뛸 단계가 없습니다." /
  방이 꽉 찼거나 지금 들어갈 수 없으면 그 방의 입장 거절 문구 그대로.
- 관리자 도구는 **사람은 관리자 혼자인 방**에서만 된다. 다른 사람이 있는 진짜 판에서는 관리자도 보통 플레이어다(공정함과 라이어·갱식마인드의 "남의 정보는 보내지 않는다" 약속 유지).
  관리자 도구가 쓰인 방에는 다른 사람이 들어올 수 없다(봇이 하나라도 있으면 사람 입장 거절 `adm_test` "관리자 시험 중인 방입니다."). 방 목록에는 그대로 보인다.

### 21-3. 봇
- 봇은 화면 없는 가짜 접속자다. 사람과 똑같은 서버 메시지를 받고 똑같은 요청을 보낸다(그래서 남의 제시어·역할을 알 수 없다). 서버의 게임 규칙에는 봇을 위한 예외가 없다.
- 아이디 `~bot1`, `~bot2`…(사람은 쓸 수 없는 글자), 이름 `봇1`, `봇2`…. 저장하지 않는다(DB·랭킹·전적에 남지 않는다).
- 0.5~1.5초 쉬고 행동한다. 무작위는 서버 난수(`hub.rng`, crypto).
- 관리자가 방을 나가거나 관리자 자리가 사라지면 봇도 모두 나간다. 관리자가 잠깐 끊긴 동안은 그대로 기다린다.
- 게임별 행동(규칙에 맞는 단순한 행동이면 충분):
  - 홀덤: 체크할 수 있으면 체크, 아니면 콜. 가끔(약 10%) 레이즈, 큰 베팅에는 가끔 폴드.
  - 블러핑: 차례가 오면 카드 1~2장을 낸다. 가끔(약 25%) 거짓말 지목.
  - 라이어: 첫 발언·발언 칸에는 정해 둔 짧은 문장, 투표는 자기 말고 무작위 한 명, 라이어 정답 맞히기는 보기 중 무작위. 그 밖의 단계는 기다린다.
  - 요트: 최대 3번 굴리며 가장 많은 눈을 남긴다. 점수 칸은 비어 있는 칸 중 가장 높은 점수(같으면 아무거나)를 두 번 눌러 기록(첫 누름이 방 전체에 보인다).
  - 갱식마인드: 그리는 차례면 첫 보기 단어를 고르고 선 몇 개를 그린다. 맞히는 차례면 가끔 아무 단어(단어 목록에서 무작위)를 채팅으로 낸다.

### 21-4. 연출 보기
- 관리자 화면에만 있는 기능. 서버에 아무것도 보내지 않고, 관리자 기기에서만 가짜 자료로 연출을 재생한다(다른 사람에게 보이지 않는다).
- 목록은 게임별: 지금 방의 게임 것, 로비에서는 전부.

### 21-5. 관리자 화면
- `me.admin` 이면 화면 오른쪽 아래에 작은 `관리자` 버튼(.adm-). 누르면 패널: [봇 추가] [봇 빼기] [단계 건너뛰기] (방 안에서만), 연출 목록, [닫기]. 결과·오류 문구는 패널 안에 한 줄.
- 일반 사용자의 화면에는 흔적이 없다.

### 21-6. 새 게임에 붙이는 방법 (앞으로 만들 게임도 이것만 하면 된다)
1. 서버: `server/admin/games/<모드>.js` 에 `createBrain(bot)`(봇 행동)과 `skip(room)`(단계 건너뛰기)을 만들고 `server/admin/games/index.js` 에 한 줄 등록.
   - `bot` = `{ id, name, rng(), send(msg), later(ms, fn) }`. `createBrain` 은 `{ onMsg(msg) }` 를 돌려준다(봇이 받는 모든 서버 메시지).
   - `skip(room)` 은 성공하면 `true`, 건너뛸 것이 없으면 `false`.
2. 화면: `client/src/admin/fx.js` 의 목록에 `{mode, id, label, play()}` 를 더한다.
3. 시험: `test/admin/<모드>.test.js` — 관리자 혼자 + 봇으로 한 판이 끝까지 간다.

### 21-7. 세부 설정 (경제 설정, 2026-11-13 사용자 요청)
- 관리자 패널의 [세부 설정] 버튼 → 전체 화면 덮개(.adm-detail). 방 안·밖 어디서나 된다. 일반 사용자에게는 이 요청이 `adm_no` 로 거절된다.
- 조절하는 것: 게임별 코인(`finish` 완주, `win` 승리 = 상대 1명당, `gapMs` 지급 간격 — 화면은 초 단위) 과 코인 교환 시세(`chipsPerCoin`, 1코인 = 몇 칩). 게임 목록은 `COIN_RULES` 의 키(bluff·liar·draw·yacht·mini·gsk). 상점 가격은 상점 개편 뒤 추가(화면에 자리 글만).
- 모양: `econ = { rules: { <코인키>: {finish, win, gapMs}, ... }, chipsPerCoin }`. 기본값 = `shared/coin/rules.js` 의 `COIN_RULES`·`CHIPS_PER_COIN`(=지금까지 쓰던 값).
- 범위(정수): finish 0~100, win 0~100, gapMs 0~3,600,000, chipsPerCoin 1~10,000 (`ECON_LIMITS`). 모든 코인키와 모든 칸이 있어야 하고, 모르는 키·소수·문자는 거절.
- 요청(관리자만): `{t:'adm', a:'econ'}` 현재값 보기 / `{t:'adm', a:'econSet', econ}` 저장 / `{t:'adm', a:'econReset'}` 기본값으로 되돌리기(저장도 함).
  세 요청 모두 답은 `{t:'admOk', a:'econ', saved, econ, defaults, limits}` (`saved` = 저장이 일어났나, `limits` = 위 범위 `{finish:[0,100], ...}`). 범위 밖이면 `error` `adm_bad` "값이 범위를 벗어났습니다."(저장 안 함), 관리자가 아니면 `adm_no`.
- 저장: 저장소 `meta` 표의 키 `econ` 한 덩어리(JSON) — Postgres 는 기존 `meta (k text, v jsonb)` 표(시작 때 `CREATE TABLE IF NOT EXISTS`), 메모리 저장소도 같은 `getMeta/setMeta`. 서버 시작 때 읽고(손상된 칸은 기본값), 바꾸면 **재시작 없이 바로** 적용(`hub.econ()`, `hub.coinRules()`).
- 읽는 곳: `hub.award`(정산)가 `hub.econ().rules` 를, 교환(`swap`)이 `chipsPerCoin` 을 읽는다. `me.wallet.chipsPerCoin` 으로 화면에 현재 시세를 준다(교환 창이 이 값을 보여 줌).

## 22. 갱식 코인·뽑기·상점·비밀번호 (2026-11-13 사용자 요청)

모든 게임(앞으로 만들 게임 포함)이 함께 쓰는 돈 **갱식 코인**. 게임을 끝내면 받고, 칩으로 바꾸거나 뽑기·상점에 쓴다. 홀덤은 코인을 주지 않는다(칩만). 출시 시점에 모두 0에서 시작한다(소급 없음).

### 22-1. 저장
- `users` 표에 칸 추가(서버 시작 때 `ALTER TABLE users ADD COLUMN IF NOT EXISTS ...`):
  `coins integer NOT NULL DEFAULT 0`(잔액), `coins_total integer NOT NULL DEFAULT 0`(지금까지 번 합, 랭킹용, 줄지 않음),
  `gear jsonb NOT NULL DEFAULT '{}'`(`{pity, owned:[아이템 id], equip:{slot: id}}`), `pin jsonb`(없으면 null. `{s: salt, h: scrypt 해시, t:[기기 토큰의 sha256, 최대 5개]}`).
- 메모리의 user: `coins, coinsTotal, gear{pity:0, owned:[], equip:{}}, pin`. `newUser`·`rowToUser`·`save`·`getOrCreate` 가 네 칸을 모두 다룬다(빠지면 통째 저장이 0으로 덮는다). 옛 행은 기본값으로 읽는다.
- 장부 `coin_log(id bigserial PRIMARY KEY, at timestamptz NOT NULL DEFAULT now(), uid text NOT NULL, kind text NOT NULL, delta integer NOT NULL, bal integer NOT NULL, chips integer NOT NULL DEFAULT 0, note jsonb)`. 덧붙이기만 한다(수정·삭제 요청 없음). `kind`: `earn`·`swap`·`draw`·`buy`. `note` 예: `{mode:'yacht', win:true}`, `{pulls:[500,2000]}`, `{item:'title.rookie'}`.
  `store.log(entry)`는 저장과 같은 줄(writes)에 세워 순서를 지키고, 실패해도 게임은 계속한다(콘솔 기록).
- 새 저장소 함수: `log`, `exists(id)`, `topCoin(n)`, `coinRank(id)`, `clearPin(id)`(접속 안 한 아이디용, 있으면 true). 메모리 저장소도 같은 함수·같은 결과(장부는 배열, 최근 10,000줄).
- 초기화: `TRUNCATE users, coin_log`. 메모리는 둘 다 비움.

### 22-2. 적립
| 게임(mode) | 끝까지 하면 | 1등 보너스(상대 1명당) | 4명 1등 | 최소 간격 |
|---|---|---|---|---|
| 블러핑 `bluff` | 1 | +1 | 4 | 30초 |
| 라이어 `liar` (라운드마다) | 1 | 이긴 편 +1 (시민의 상대 = 1, 라이어의 상대 = 시민 수) | 시민 2 / 라이어 4 | 45초 |
| 갱식마인드 `draw` | 2 | +2 | 8 | 2분 |
| 요트다이스 `yacht` | 3 | +4 | 15 | 4분 |
| 미니게임 `mini` (2026-11-13) | 0 | 판에서 이긴 사람 1 (기권·나가기·무승부 0) | 1 | 1분 |
| 홀덤 `holdem` | 없음 | 없음 | 0 | |

- 표는 `shared/coin/rules.js`의 `COIN_RULES` 한 곳. 받는 코인 = `finish + (이겼으면 win × 상대 수)`.
- **끝까지 한 사람**: 판이 시작될 때 참가자였고 판이 끝날 때도 그 방에 자리(잠깐 끊겨 유예 중인 사람 포함)가 있는 사람. 게임 안에서 탈락한 사람(블러핑에서 총 맞음)은 끝까지 한 것이다.
- **못 받는 사람**: 중간에 나감·기권·유예 지나 쫓겨남, 관전자, 판 도중 난입한 사람, 봇.
- **상대 수** = 판을 시작한 사람 수 − 1(중간에 나간 사람도 센다). 라이어만 위 표대로.
- **동점 1등**: 전원이 보너스를 온전히 받는다(나누지 않는다).
- **무효**: 라이어의 무효 라운드(`void`)는 아무도 못 받는다. 요트·갱식마인드에서 다른 사람이 모두 나가 혼자 남아 끝난 판(`reason==='alone'`)도 아무도 못 받는다(부계정으로 시작했다 나가는 꼼수 방지). 블러핑도 같은 경우(남은 한 명이 나머지가 나가서 이긴 판)는 끝까지 한 사람이 2명 이상일 때만 준다. 방에 봇이 한 명이라도 있으면(관리자 시험 방) 아무도 못 받는다.
- **최소 간격**: 같은 사람이 같은 게임에서 코인을 받은 지 표의 시간이 안 지났으면 이번 것은 0. 서버 메모리에만 기억한다(`hub.now`). 0 이어도 판을 끝까지 한 사람은 공통 결과 화면(`wait.result.gain`)에 흐린 "0" 으로 보인다. 중간에 나간 사람·관전자는 줄이 없고, 봇 방은 모두 0.
- 표의 값은 관리자 세부 설정(21-7)으로 바뀐다. `shared/coin/rules.js` 의 `COIN_RULES` 는 기본값이다. 갱스껄(`gsk`) 줄: 완주 2, 승리 2(상대 1명당), 간격 120초(갱식마인드와 비슷한 길이로 정함). 혼자 남은 판(`alone`)은 지급 없음.
- **라이어 시점**: 라운드가 `result` 단계에 들어간 순간(정체 공개·정답 판정이 끝난 뒤)에만 준다. 그 전에는 코인 잔액도 알림도 바뀌지 않는다. 갱식마인드는 최종 순위가 나올 때, 요트는 결과 화면, 블러핑은 승자가 정해질 때.
- 서버 함수 하나: `hub.award(room, mode, rows)`, `rows = [{id, won, opp}]`(끝까지 한 사람만, `opp` = 그 사람의 상대 수). 하는 일: 봇 방·최소 간격·봇 아이디 거르기 → `coins`·`coinsTotal` 더하기 → 저장 → 장부 `earn` → `me` 다시 보내기. 돌려주는 값 `{[id]: 받은 코인}` 을 Shell 이 `wait.result.gain` 에 싣는다(7-3).
- 부르는 곳: 블러핑은 `server/rooms.js` `afterBluff`의 `done`에서 직접. (2026-11-13 묶음 2 이후) 모든 게임은 판 끝에 공용 방 틀의 `ctx.finish(rows)` 를 판마다 한 번 부르고, 틀이 등록표 `coin` 키로 `hub.award` 를 부른다(COMMON-CONTRACT 1-3, D4. 옛 `server/coin/hooks.js` 감싸기는 지웠다): 라이어 결과(`winner`, `liarId`, `players − dropped`), 요트 결과(`ranks`, `winners`), 갱식마인드 순위(`rank===1`, `left`).

### 22-4. 뽑기
- 1회 10코인, 10연 100코인. 방 밖에서만. 결과는 서버가 `hub.rng`(crypto)로 정하고 바로 계정 칩에 더한다. 화면은 받은 결과를 연출만 한다.

| 등급 | 칩 | 확률 | 색 | 평균 기여 |
|---|---|---|---|---|
| 0 동 | 500 | 73.10% | 회갈색 | 365.5 |
| 1 은 | 2,000 | 25.00% | 파랑 | 500.0 |
| 2 금 | 5,000 | 1.69% | 보라→금 | 84.5 |
| 3 잭팟 | 20,000 | 0.20% | 금 | 40.0 |
| 4 갱식 잭팟 | 100,000 | 0.01% | 무지개 | 10.0 |

- 합 100.00%, 1회 평균 **1,000칩**(낸 값 1,000칩 대비 100.0%). 추첨은 0~9,999 정수 하나를 뽑아 누적 가중치(7310·2500·169·20·1)와 비교한다. 표는 `shared/coin/gacha.js` 한 곳.
- **천장**: 금 이상이 안 나온 뽑기를 센다(`gear.pity`). 79번 연속 안 나오면 80번째는 금(5,000) 확정. 금 이상이 나오면 0으로. 화면에 "천장까지 N번". 천장 포함 평균 약 1,021칩(102.1%).
- **10연 보장**: 10개가 전부 500이면 마지막 하나를 2,000으로 바꾼다(4.4% 확률로 발동, 1회당 +6.5칩). 10연 평균 약 1,028칩(102.8%). 천장 계산은 10개를 차례로 센 뒤 보장을 적용한다.
- 한 계정 0.3초에 한 번(그 안의 요청은 무시).
- **자랑 알림**: 금(5,000)은 로비에 있는 사람에게, 잭팟 이상(20,000~)은 접속한 모든 사람에게 `{t:'coin', a:'news'}`. 관리자 계정의 뽑기는 알리지 않는다.
- **연출**(`.gc-`, 3D 없음, `?nogl=1`에서도 같음, 전체 화면 덮개):
  1. 누르면 캡슐이 흔들린다. 서버 답이 와도 최소 0.6초는 흔든다.
  2. 캡슐 빛이 회갈색에서 시작해 결과 등급까지 한 단계씩 올라간다(단계마다 0.35초, 올라갈 때마다 짧게 멈칫). 결과가 동(500)일 때 셋 중 한 번은 파랑으로 깜빡였다 꺼지는 "아깝다" 연출(화면에서만 정하는 꾸밈, 결과와 무관).
  3. 캡슐이 열리며 칩 숫자가 0에서 결과까지 올라간다(0.6초). 금: 화면 흔들림 + 금색 번쩍. 잭팟: 화면 전체 금색 + 칩 비 2초. 갱식 잭팟: 무지개 + 칩 비 4초 + 큰 글자.
  4. 10연: 캡슐 10개가 0.25초 간격으로 차례로 열린다. 가장 높은 등급을 맨 마지막에 연다. 끝에 합계. [건너뛰기]는 언제나 누를 수 있고 누르면 바로 결과.
  5. 끝나면 [한 번 더] [10연] [닫기]. 코인이 모자라면 버튼이 흐려진다. `prefers-reduced-motion`이면 1~3을 건너뛰고 결과만.
  - 연출 중 새로고침해도 칩은 이미 들어가 있다. 소리는 다음 과제(실기기 확인 필요).

### 22-8. 비밀번호(선택, 숫자 4자리)
- 기본은 지금처럼 아이디만. 비밀번호가 걸린 아이디만 아래를 따른다. `관리자`는 21절 방식 그대로이고 PIN을 걸 수 없다(`pin_adm`).
- 저장: salt 16바이트 + `crypto.scrypt`(비동기) 32바이트 해시만. PIN 원문은 서버·기기 어디에도 저장하지 않는다.
- 로그인 `{t:'login', id, pin?, tok?, newPin?}`:
  1. PIN 없는 아이디: 지금과 같다. `newPin`이 있고 이번 로그인으로 **새로 만들어진** 아이디이면 PIN을 걸고 토큰을 준다. 이미 있던 아이디에 `newPin`이 오면 로그인시키지 않고 `pin_exists`.
  2. PIN 있는 아이디: `tok`이 맞으면 통과. 아니면 `pin`이 맞아야 통과하고 새 토큰을 준다. 둘 다 없거나 토큰이 틀리면 `pin_need`(틀린 횟수로 세지 않음). PIN이 틀리면 `pin_bad`.
  3. 통과 전에는 계정 정보를 보내지 않고, **기존 접속을 끊지 않는다**(자리 이어받기는 맞는 PIN·토큰이 있을 때만).
- 잠금: 한 아이디에서 10분 안에 5번 틀리면 10분 동안 PIN 입력을 거절(`pin_lock`, 맞는 PIN도). 토큰 로그인은 잠금 중에도 된다. 서버 메모리에 기억.
- 기기 토큰: 서버가 만든 32바이트 난수(16진수). 서버는 sha256만 저장(아이디당 최근 5개). 기기는 `gs.tok`에 저장해 자동 로그인에 쓴다. 로그아웃하면 기기에서 지우고 `{t:'pin', a:'forget'}`로 서버에서도 지운다.
- 로비 프로필의 "비밀번호": 걸기(PIN 없을 때), 바꾸기·없애기(지금 PIN 필요, 틀리면 위 잠금에 센다). 걸거나 바꾸면 그 아이디의 다른 기기 토큰은 모두 무효, 이 기기에 새 토큰.
- 잊어버렸을 때: 관리자가 `{t:'adm', a:'pinclr', id}` → 그 아이디의 PIN·토큰·잠금을 지운다(방 안팎 어디서나, 관리자만). 성공 `{t:'admOk', a:'pinclr'}`, 없는 아이디 `adm_noid` "없는 아이디입니다.".

### 22-9. 초기화 보호 (17절을 고침)
- `{t:'login', id:'초기화'}` → `{t:'resetAsk'}`는 그대로. 확인 화면에 **관리자 비밀번호 칸**이 생긴다.
- `{t:'reset', confirm:true, pw}`: `pw`가 관리자 비밀번호(`ADMIN_KEY`, 없으면 9975)와 같아야 실행. 틀리면 `adm_pw`, 잠금 중이면 `adm_lock`. 관리자 로그인과 **같은 잠금**(10분 5번)을 쓴다. 나머지(1분 제한 등)는 17절 그대로.

### 22-18. 상점 진열 바꾸기 (2026-11-13 사용자 요청. 22-5·22-16 의 "잡템·흔템은 상점에서 판다"를 고침)
- 상점은 품목을 한꺼번에 다 보여 주지 않는다. **사람마다 다른 진열** 두 줄만 보인다. 화면 디자인은 지금 상점("딜러의 테이블")을 그대로 쓰고, 품목 칸만 두 줄로 바꾼다(사용자 참고 그림: 위 "오늘의 상품 · 새로고침까지 m:ss", 아래 "상시 상품", 칸마다 그림 + 가격 버튼, 코인 모자라면 빨간 버튼).
- **위 줄(a)**: 5칸, **5분**마다 바뀜. 칸마다 등급을 따로 뽑는다: 잡템 85% / 흔템 15%.
- **아래 줄(b)**: 5칸, **1시간**마다 바뀜. 칸마다: 흔템 77% / 컨셉 20% / 레전드 3%. 갱식은 상점에 없다.
- 후보: 그 등급에서 `cap:true` 인 품목(모든 slot 섞임) 중 **아직 안 가진 것**. 한 줄 안에서 겹치지 않고, 두 줄끼리도 겹치지 않는다. 그 등급 후보가 없으면 다른 등급(가까운 아래 → 위)으로, 모두 없으면 칸을 비운다. `title.jackpot`·`title.trashking` 은 절대 안 나온다.
- 가격: `it.price` 가 있으면 그것, 없으면 등급 가격(컨셉 400, 레전드 1,500 코인). 함수 `priceOf(it)` 한 곳(`shared/coin/stock.js`).
- 바뀌는 시각은 모두 같은 벽시계 기준: 위 줄 `floor(now / 300000)`, 아래 줄 `floor(now / 3600000)`(서버 시계 `hub.now`). 진열은 그 기간에 그 사람에게 처음 필요할 때 서버가 `hub.rng` 로 뽑아 `gear.stock = {a:{p, ids}, b:{p, ids}}` 에 저장한다(재시작해도 같은 기간이면 그대로). 사고 나도 칸은 그대로 남고 "보유"로 보인다.
- 사기 `{t:'coin', a:'buy', id}`: 지금 기간의 내 진열(a 또는 b)에 있는 품목만. 아니면 `shop_gone` "진열이 바뀌었습니다.". 나머지(`coin_room` `coin_low` `shop_own`)는 그대로. 장부 `buy`.
- `me.wallet.stock = {a:{ids:[5칸, 빈 칸은 null], left}, b:{ids, left}}` (`left` = 바뀔 때까지 ms). 화면은 받은 순간부터 `left` 를 세어 "새로고침까지 m:ss"를 보이고, 0이 되면 `{t:'coin', a:'stock'}` 를 보낸다 → 서버가 새 진열로 `me` 를 다시 보낸다(1초에 한 번까지, 방 안팎 어디서나 됨).
- 끼기·빼기와 내 물건 보기는 상점이 아니라 꾸미기 쪽(그 전까지는 상점의 기존 보유 목록을 그대로 둬도 됨).
- 시험(`test/coin/stock.test.js`): 같은 기간 두 번 → 같은 진열, 기간이 바뀌면 다시 뽑음, 안 가진 것만·겹침 없음, 잭팟·수집 칭호·갱식 없음, 씨앗 난수 10만 번 등급 비율 ±1%p, 진열에 없는 품목 사기 `shop_gone`, 진열 품목 사기 성공. smoke.mjs 의 상점 사기 줄은 진열의 첫 칸을 산다.
- 오류 글 추가: `shop_gone` "진열이 바뀌었습니다.". 22-10 표의 `buy` 실패 코드에 `shop_gone`, 화면 → 서버에 `{t:'coin', a:'stock'}`.
- 남은 일 5번("오늘의 패")은 이것으로 대체한다.

### 22-20. 미니게임 코인 베팅 맡기기 (2026-11-13 사용자 요청)
- 서버 함수 둘(server/coin/wallet.js): `hub.stake(key, rows, {mode, code})`, `hub.settleStake(key, winnerId|null)`. `rows = [{id, n}]`(n 은 1 이상 정수, 사람 2명 이상, 봇 불가). 모두 되거나 하나도 안 된다(잔액·중복·봇 검사 뒤에 한꺼번에 뗀다). 떼 간 코인은 계정에도 `gear.escrow = {code, n}` 로 적혀 저장된다.
- `settleStake`: 이긴 사람이 판돈 전부(자기 것 + 상대 것), `null` 이면 각자 자기 것을 돌려받는다. 같은 key 로 두 번 부르면 두 번째는 아무 일도 없다. 번 몫(상대 판돈)만 `coinsTotal` 에 더한다.
- 서버가 꺼졌다 켜져 아무도 맡고 있지 않은 `gear.escrow` 는 그 계정이 다시 로그인할 때 `hub.recoverStake` 가 돌려준다. 정상 종료(hub.close)는 방의 `flush` 가 먼저 돌려준다.
- 알림: 매치 끝 공통 결과(`wait.result`)의 코인 칸에 합쳐 보인다(`gain` = 승리 코인 + 베팅 증감, `add: {label:'베팅', by}` 로 나눠 한 줄 설명). 장부 종류: `stake`(떼기, 음수) `stake_win`·`stake_lose`·`stake_back`(정산, 돌려받은 양).
- 쓰는 곳: 미니게임 매치(docs/mini/PLAN.md 5절).
