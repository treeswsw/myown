# 갱식마인드 기획서 (GDD) — v0.2

갱식 클럽 안의 네 번째 게임. 한 사람이 단어를 그림으로 그리고 나머지가 채팅으로 맞힌다.
표시: ✅ 사용자가 정함 · ☑ 기본안(사용자가 정하지 않아 기획이 정함. 바꿀 수 있음) · ⬜ 미정(사용자 확인 필요, 13절).
시안: `design/draw/index.html`(정적, 가짜 데이터) · 스크린샷 `design/draw/shots/`.
이 문서는 기획이다. 코드는 아직 없다. 3D·소리·실기기 느낌(iPad·Safari·펜슬)은 전부 **미확인(실기기 확인 필요)**.

## 1. 한 줄 소개와 이름

친구 2~8명이 각자 기기로 방에 모여, 돌아가며 한 명이 단어를 그리고 나머지가 채팅으로 맞히는 그림 퀴즈.

- ✅ 이름: **갱식마인드**(사용자 확정 2026-11-13).
  - 코드에서는 이름을 **한 곳**에만 적는다: `shared/draw/name.js`의 `GAME_NAME`. 화면·오류 문구는 전부 이 값을 쓴다(나중에 바꾸기 쉽게). 시안도 `index.html` 맨 위 `GAME_NAME` 하나다.
- "캐치마인드"는 넷마블의 게임 이름이다. **이름·로고·캐릭터·그림·화면 꾸밈은 쓰지 않는다.** 규칙의 흐름과 배치(좌우 플레이어 칸, 가운데 그림판)만 참고했다.
  그림판 참고 이미지(사용자 제공)의 상표·스프링 노트 꾸밈도 쓰지 않는다.

## 2. 뼈대

- ✅ 갱식 클럽과 같은 사이트·같은 아이디·같은 프로필 사진·같은 로비. 설치 없는 웹.
- ✅ 라이어게임과 같은 **숨김 스위치**로 공개한다(11절).
- ✅ 규칙은 원작과 같게. 웹이라서 바꾼 것은 3-2절에 이유와 함께 모았다.
- ✅ 기기: 휴대폰 가로, PC, iPad(손가락·펜슬·마우스). 세로로 들면 기존 "가로로 돌려 주세요" 안내.
- ☑ **3D 장면을 쓰지 않는다.** 평면 화면만(그림 그리기가 끊기지 않게 하고 배터리를 아낀다). 배경은 어두운 클럽 톤, 그림판만 밝은 종이.
- ☑ 인원 2~8명(원작 8명 이하). 2명이면 서로 번갈아 그린다.
- ☑ 채팅·이모티콘·사운드는 사이트의 것을 그대로 쓰되, 그리는 사람은 그리는 동안 전부 막는다(9절 유출 방지).

## 3. 규칙

### 3-1. 원작 규칙 (조사 결과)

출처는 14절. 나무위키 등은 이 환경에서 직접 열 수 없어 검색 요약으로 확인했다. "확인 못 함"은 그대로 적었다.

| 항목 | 원작(PC판) | 확인 |
|---|---|---|
| 인원 | 8명 이하 | 확인 |
| 출제 순서 | 방에 있는 사람이 한 명씩 돌아가며 출제(정답자가 다음 출제자가 되는 방식 아님) | 확인 |
| 단어 | 문제 은행에서 한 단어를 준다(고르지 않음). 출제자에게만 보인다 | 확인(화면 "문제" 칸) |
| 시간 | 문제당 2분 20초 | 확인 |
| 문제 수 | 한 판 20라운드 | 확인 |
| 무입력 넘김 | 20초 동안 그림판을 누르지 않으면 자동으로 넘어간다 | 확인 |
| 정답 | 채팅으로 입력. 가장 먼저 맞힌 사람이 정답자 | 확인 |
| 한 문제의 끝 | 정답자가 한 명 나오면 그 문제가 끝난다 | **확인 못 함**(기억과 화면의 "정답 N" 표시로 추정) |
| 점수 | 화면에는 사람마다 "정답 N". 최근 판은 출제자와 정답자가 함께 점수를 얻고 빨리 맞힐수록 높다 | 확인 |
| 포기 | 출제자에게 "포기" 버튼이 있다 | 버튼은 확인, 처리 방식은 확인 못 함 |
| 힌트 | 공식 힌트 없음. 출제자가 구석에 점으로 글자 수를 알려 주는 관행 | 확인 |
| 금지 | 글자·숫자를 쓰면 안 된다. 출제자는 채팅 불가("그림으로만 설명해 주세요") | 확인 |
| 그림 도구 | 색 5가지(검정·빨강·파랑·초록·노랑), 지우개, 전체 지우기 | 확인(화면) |

### 3-2. 우리 규칙 = 원작 그대로 + 웹에서 바꾼 것

그대로 가져오는 것: 출제자만 단어를 봄, 채팅으로 맞히기, 2분 20초, 포기 버튼, 무입력 20초 넘김, 글자·숫자 금지, 출제자 채팅 금지,
출제자와 정답자가 함께 점수를 얻고 빨리 맞힐수록 높음(원작 최근 판).

바꾼 것(✅ 사용자 결정, ☑ 기본안):

| # | 바꾼 것 | 이유 |
|---|---|---|
| 1 | ✅ **출제 순서를 방장이 고른다**: 순서대로 / 맞힌 사람 / 랜덤 (3-3) | 사용자 결정 |
| 2 | ✅ **라운드 수를 따로 고른다**(1·**2**·3·5). 한 라운드 = 모두 한 번씩 그리기. 원작은 20문제 고정 | 사용자 결정. 인원이 달라도 그리는 횟수가 같다 |

### 3-3. 출제 순서와 라운드 (✅ 사용자: 순서대로 / 맞힌 사람이 그리기 / 랜덤, 라운드 수는 따로)

**라운드의 뜻은 세 방식 모두 같다: 한 라운드 = 방에 있는 사람이 모두 한 번씩 그린다.**
문제 수 = 인원 × 라운드 수(예: 5명 × 2라운드 = 10문제). 라운드 수 선택지 1·**2**·3·5(☑ 기본 2).
한 라운드 안에서는 **한 사람이 한 번만** 그린다 — 이것이 "한 사람이 계속 그리는 일"을 막는 장치다(☑).

| 방식 | 다음에 그리는 사람 |
|---|---|
| **순서대로**(☑ 기본) | 자리 순서(들어온 순서). 판의 첫 출제자만 무작위 |
| **맞힌 사람** | 방금 문제를 **가장 먼저 맞힌 사람**. 그 사람이 이번 라운드에 이미 그렸으면 그다음으로 빨리 맞힌 사람. 맞힌 사람 중에 아직 안 그린 사람이 없거나 아무도 못 맞혔으면, 아직 안 그린 사람 중 자리 순서로 다음 사람. 판의 첫 출제자는 무작위 |
| **랜덤** | 이번 라운드에 아직 안 그린 사람 중에서 매 문제 무작위(crypto 난수). 라운드가 바뀔 때 방금 그린 사람이 곧바로 또 뽑히지는 않는다(2명일 때 제외) |

- 모두 한 번씩 그리면 다음 라운드. "이미 그림" 기록을 비운다.
- 도중에 들어온 사람은 **다음 라운드부터** 그리는 순서에 들어간다(맞히기는 다음 문제부터 바로). 한 라운드의 문제 수는 그 라운드를 시작할 때의 인원이다.
- 끊겼거나 나간 사람 차례는 건너뛴다(그 라운드에 그린 것으로 친다).
- ☑ "맞힌 사람" 방식을 "제한 없이 맞힌 사람이 계속 그리기"로 하지 않은 이유: 잘 맞히는 두 사람만 번갈아 그리고 나머지는 한 번도 못 그릴 수 있다.

### 3-4. 한 문제의 끝과 점수 (✅ 사용자: "여러 명이 맞힐 때까지, 빠를수록 높은 점수")

- 한 문제는 **시간이 끝나거나, 그리는 사람을 뺀 모두(접속 중인 사람)가 맞히면** 끝난다. 그 밖에 포기·넘김·그리는 사람 나감.
- ☑ 첫 정답이 나왔을 때 남은 시간이 30초보다 길면 **30초로 줄인다**(기다리는 시간이 길어지지 않게. 화면에 "30초 남았어요").
- 맞힌 사람 점수 = **40 + 60 × (맞힌 순간 남은 시간 ÷ 그리는 시간)**, 소수점 반올림. **첫 정답자는 +20.**
  - 예(2분 20초, 5명이 맞히는 중): 18초에 첫 정답 → 40 + 52 + 20 = **112점**. 시간이 30초로 줄고, 25초 남기고 맞히면 40 + 11 = **51점**, 14초 남기고 맞히면 **46점**.
  - 한 문제에서 맞힌 사람은 최소 40점, 최대 120점.
- 그린 사람 점수 = **100 × (맞힌 사람 수 ÷ 맞힐 수 있던 사람 수)**, 반올림. 예: 5명 중 3명 → 60점. 모두 맞히면 100점.
- 아무도 못 맞히면 모두 0점. 포기·넘김·나감이면 그린 사람은 0점, 이미 맞힌 사람의 점수는 그대로.
- 순위: 점수 큰 순 → 맞힌 횟수 큰 순 → 같으면 공동 순위.

### 3-5. 맞힌 뒤의 채팅 (☑ 힌트 흘리기 방지)

- 정답 글 자체는 **아무에게도 채팅으로 보이지 않는다.** 모두에게 "민수 님 정답!" 알림만 뜨고, 그 사람 칸이 초록색 "맞힘"으로 바뀐다.
- 맞힌 사람이 그 뒤에 쓰는 글은 **이미 맞힌 사람들과 그리는 사람에게만** 보인다(초록 글씨 "정답자끼리"). 아직 못 맞힌 사람에게는 보내지 않는다.
- 맞힌 사람의 사진 이모티콘·사운드는 정답 공개 전까지 막는다(그림·이름으로 흘릴 수 있다). 기본 이모티콘 6개는 된다.
- 아직 못 맞힌 사람의 글은 모두에게 보인다(오답 구경이 재미).
- 맞힌 사람 화면에는 그때부터 단어가 보인다(`□□□` 대신 `짜장면`).
- 다시 들어온 사람에게 주는 채팅 기록에도 같은 규칙을 적용한다(못 맞힌 사람에게 정답자끼리 한 글을 주지 않는다).

## 4. 한 판의 진행

```
방 대기 → [단어 고르기 10초 → 그리기 2분 20초 → 정답 공개 5초] × (인원 × 라운드 수) → 최종 순위 → 방 대기(또는 한 판 더)
```

| 단계 | 무슨 일 | 끝 조건 | 시간 |
|---|---|---|---|
| 방 대기 `lobby` | 방장이 설정(출제 순서, 라운드 수, 그리는 시간, 주제)을 고르고 시작. 2명 이상 | 방장 "시작" | 없음 |
| 단어 고르기 `pick` | 그리는 사람에게 단어 3개(주제 표시). 나머지는 "○○ 님이 고르는 중" | 고름 / 10초 지나면 첫 단어 | 10초 |
| 그리기 `draw` | 그리는 사람: 단어·도구·포기. 나머지: 글자 수 칸·정답 입력. 맞힌 사람은 "맞힘" 표시 | ① **모두 맞힘** ② 시간 끝(첫 정답 뒤에는 최대 30초) ③ 포기 ④ 20초 안에 첫 선 없음 ⑤ 방장이 넘김 ⑥ 그리는 사람이 나감 | 2분 20초(60초·90초·**2분 20초** 중 방장 선택) |
| 정답 공개 `reveal` | 그림은 그대로 두고 정답, 맞힌 사람과 얻은 점수, 그린 사람 점수. 아무도 못 맞혔으면 "시간 끝! 정답은 ○○" | 자동 | 5초(건너뛰기 없음) |
| 최종 순위 `final` | 1~3등 단상 + 나머지 목록(점수, 맞힌 횟수) | 방장 "한 판 더" 또는 "방으로" | 없음(방장이 누를 때까지) |

- 출제 순서는 3-3. 판의 첫 출제자는 무작위(crypto 난수).
- 한 방에서 이미 나온 단어는 그 방에서 다시 나오지 않는다(보여 준 3개 중 안 고른 것은 다시 나올 수 있다).
- 시간은 서버가 잰다. 화면은 서버가 준 끝 시각(`endsAt`)으로 줄어드는 막대와 숫자만 그린다.

## 5. 단어

- `server/liar/words.json`을 **읽기만 해서 재사용할 수 있다**(확인함). 구조: `sets.mine.topics[]`(11주제 × 100개 = 1,100개), 단어마다 `w`(단어)와 `alt`(다른 이름, 120개 단어에 있음). 가장 긴 단어 12자.
  - 라이어 폴더는 gamemine 과 같게 유지해야 하므로 **파일을 고치거나 옮기지 않는다.** 갱식마인드 서버가 같은 파일을 불러 쓴다.
  - `alt`는 정답 판정의 "다른 이름"으로 그대로 쓴다.
- ☑ 기본으로 쓰는 주제 8개(800개): 음식, 동물, 직업, 장소, 스포츠, 물건, 취미, 탈것.
- ☑ 기본으로 끄는 주제 3개: 영화·만화, 나라·도시, 인물 — 그림으로 설명하기 어렵고 글자를 쓰고 싶어진다. 방장이 방 설정에서 켤 수 있다.
- ☑ 스타 버전 묶음(`sets.star`)은 1차에서 쓰지 않는다(연예인·브랜드·롤챔프는 그리기 어렵다).
- ⬜ 그림용으로 단어를 따로 고르는 일(너무 어려운 단어 빼기)은 실제로 해 본 뒤 결정. 필요하면 `docs/draw/WORDS.md`에 "빼는 단어" 목록만 둔다(원본은 그대로).

### 6-2. 결정 (✅ 사용자: "직관적으로 딱 필요한 기능만", ☑ 세부)

**남긴 것 5가지 + 색 + 굵기.** 처음 보는 사람이 설명 없이 쓸 수 있는 것만.

| 항목 | 결정 | 한 줄 근거 |
|---|---|---|
| 펜 | 기본 선택 | 그리기의 전부 |
| 지우개 | 종이 색으로 덧칠하는 펜(굵기는 펜의 약 2.5배) | 펜과 같은 방식이라 받는 쪽 그림도 똑같이 나온다 |
| 되돌리기 | 마지막 한 일(선 하나 또는 전체 지우기)을 취소. **그 문제 안에서는 횟수 제한 없이** 처음까지 | 손가락 그림은 실수가 잦다. 지우개보다 빠르다 |
| 다시 하기(앞으로 가기) | ✅ 되돌린 것을 다시 살린다. 되돌리기 바로 옆. 살릴 것이 없으면 흐리게 | 사용자 결정("되돌리기랑 앞으로가기는 무조건") |

| 색 | **12색**, 2줄×6칸, 누르면 바로 바뀜. 고른 색에 흰 테두리 | 한눈에 다 보이고 한 번에 눌린다. 휴대폰에서도 칸이 28px 이상 |

**뺀 것과 이유**

| 뺀 도구 | 이유 |

| 네모·원(테두리/채움) | 손으로 그리는 게 더 빠르고 버튼 4개가 휴대폰 자리를 차지한다 |
| 직선 | 쓸 일이 드물다 |
| 채우기(페인트 통) | 부드러운 선(가장자리가 흐림)과 만나면 틈·테두리가 남고 기기마다 결과가 달라질 수 있다. 굵게 24로 대신 칠한다. ⬜ 해 보고 아쉬우면 2차에 추가 |

되돌리기·다시 하기 규칙:
- 그 문제의 "한 일 목록"(선, 전체 지우기)과 "지금 위치"를 서버가 기억한다. 되돌리기는 위치를 한 칸 뒤로, 다시 하기는 한 칸 앞으로.
- **새 선을 긋거나 전체 지우기를 하면 다시 하기 목록은 비워진다**(되돌린 것은 사라진다).
- 전체 지우기도 한 일 하나다. 되돌리면 그림이 통째로 돌아오고, 다시 하면 또 지워진다.
- 횟수 제한은 따로 없다(한 문제의 선은 최대 600개). 문제가 바뀌면 목록을 비운다.
- 다른 사람 화면에도 같은 순서로 전달한다(`drUndo`, `drRedo`). 받는 쪽도 같은 목록과 위치를 갖고 다시 그린다.

단축키(PC, 그리는 사람만. 그리는 사람은 채팅을 못 쓰니 글자 키와 겹치지 않는다): `B` 펜 · `E` 지우개 · `1` `2` `3` 굵기 · `Ctrl/⌘+Z` 되돌리기 · `Ctrl/⌘+Shift+Z` 또는 `Ctrl+Y` 다시 하기. 전체 지우기와 포기는 단축키 없음(실수 방지).

### 6-3. 선 부드러움 (✅ 사용자: "부드럽게 그림이 그려지게")

수치는 시작값이다. 느낌은 **미확인(실기기 확인 필요)** — 사용자가 iPad·휴대폰에서 그려 보고 조절한다.

| 항목 | 기준 |
|---|---|
| 좌표 | 그림판은 항상 4:3, 내부 좌표 **1600×1200**(= 800×600의 반 픽셀 단위 정수). 화면 크기가 달라도 모두 같은 그림을 본다 |
| 입력 | Pointer Events 하나로 마우스·손가락·펜을 받는다. `pointermove`마다 `getCoalescedEvents()`로 **브라우저가 묶어 버린 중간 점까지 전부** 쓴다(없으면 마지막 점만) |
| 점 간격 | 앞 점과 **2px(800 기준) 미만**이면 버린다. 한 번 누르고 떼기만 하면 점 하나(동그라미)로 그린다 |
| 떨림 줄이기 | 새 점 = 앞 점 35% + 손 위치 65%(가벼운 보정). 펜슬은 보정 없음(100%). ⬜ 값은 실기기에서 조절 |
| 곡선 | 점과 점을 직선으로 잇지 않는다. **가운뎃점 2차 베지어**: 이웃한 두 점의 가운뎃점에서 다음 가운뎃점까지, 실제 점을 조절점으로 `quadraticCurveTo`. 각이 지지 않는다 |
| 선 끝·이음 | `lineCap = 'round'`, `lineJoin = 'round'` |
| 선명함 | 캔버스 실제 크기 = 보이는 크기 × `devicePixelRatio`(최대 2). 화면 크기가 바뀌면 저장된 선으로 다시 그린다(그림이 흐려지거나 사라지지 않는다) |
| 내 화면 | **누르는 즉시 내 화면에 먼저 그린다**(서버 답을 기다리지 않는다). 입력 처리 안에서 바로 그리고, 캔버스는 `desynchronized: true` 힌트 |
| 보내기 | 점을 모아 **60ms마다 한 번**(초당 약 16번. 연결당 초당 20개 제한 안쪽). 한 번에 최대 64점 |
| 받는 쪽 | 받은 점을 **같은 곡선 방식**으로 그린다. 한 묶음을 한꺼번에 찍지 않고 다음 화면 갱신 2~3번에 나눠 이어 그려 뚝뚝 끊겨 보이지 않게 한다 |
| 되돌리기·다시 하기 | 한 일 목록의 지금 위치까지 다시 그린다. 선 20개마다 중간 그림을 저장해 빨리 다시 그린다 |
| 손바닥 | ① 그림판은 `touch-action: none`(화면이 밀리거나 확대되지 않음) ② **먼저 닿은 한 점만** 그린다(나중에 닿은 손바닥·둘째 손가락 무시) ③ **펜슬이 한 번이라도 닿으면 그 뒤로 그림판은 펜만 받는다**(손가락·손바닥은 그리지 않음. 버튼은 손가락으로 누를 수 있다. 방을 나가면 풀림) ④ 브라우저가 "손바닥이었다"고 알려 주면(`pointercancel`) 그 선을 통째로 취소한다 ⑤ 닿은 면이 60px보다 넓으면 무시(알려 주는 기기만) |
| 그 밖 | 그림판에서 길게 누르기 메뉴·글자 선택·두 번 눌러 확대를 막는다. 그리는 중에 손이 그림판 밖으로 나가도 선이 끊기지 않는다(`setPointerCapture`) |

## 8. 규칙 체크리스트 (13항목)

**① 누가, 몇 명, 로그인**
- ✅ 친구끼리. ☑ 한 방 2~8명. 기존 아이디 로그인 그대로(비밀번호 없음, 자동 로그인, 같은 아이디로 다시 들어오면 자리 이어받기).

**② 저장할 것**
- ☑ 아이디별 `users.stats.draw = {games, wins, correct, points}`(판 수, 1등 횟수, 맞힌 횟수, 누적 점수). 새 표를 만들지 않는다.
- ☑ 그림·채팅·방은 저장하지 않는다(방이 사라지면 함께 사라진다). ☑ 전체 랭킹은 1차에 없다(로비 프로필에 "그림 1등 N번"만).

**③ 핵심 흐름** — 4절 표.

**④ 각 단계의 끝 조건·시간** — 4절 표. 모든 시간은 서버가 잰다.

**⑤ 나가기·끊김·재접속**
- 맞히는 사람이 끊김: 자리 60초 유지(기존 규칙). 게임은 그대로 간다. 돌아오면 지금까지의 그림을 한 번에 받는다(10절 `drSync`).
- 그리는 사람이 끊김: **15초** 기다린다(시간은 계속 흐른다). 돌아오면 이어서 그린다. 안 돌아오면 그 문제는 정답 없이 끝나고 다음 사람.
- 그리는 사람이 나감: 그 문제 즉시 끝(점수 없음), 정답 공개 후 다음 사람.
- 끊긴 사람 차례가 오면 건너뛴다(그 사람의 그릴 횟수는 줄어든다).
- 남은 사람이 1명이 되면 판을 끝내고 방 대기로 돌아간다(점수는 그때까지 것을 저장).
- 진행 중에 들어온 사람: **다음 문제부터 바로 맞힐 수 있다.** 출제 순서는 맨 뒤에 붙는다. 들어온 순간 지금 그림을 받는다(관전만 하는 상태를 만들지 않는다 — 단어를 모르는 사람이 채팅으로 정답을 흘리는 문제를 없앤다).
- 방장이 나가면 기존 규칙대로 가장 먼저 들어온 사람이 방장.

**⑥ 점수** — 3-4절. 맞힌 사람 40~120점(빠를수록 높고 첫 정답자 +20), 그린 사람 0~100점(맞힌 사람 비율). 방 점수는 한 판이 끝나면 0으로. 누적은 ②.

**⑦ 결과 표시·시간·건너뛰기**
- 정답 공개: 5초, 자동, 건너뛰기 없음. 정답, 맞힌 사람마다 얻은 점수, 그린 사람 점수, 다음 차례 이름.
- 최종 순위: 방장이 "한 판 더"(같은 설정으로 바로 시작) 또는 "방으로"를 누를 때까지. 다른 사람은 "나가기"만.

**⑧ 만나는 방법·방장 권한**
- 로비 "새 게임"에서 "갱식마인드" → 방 만들기. 방 목록에서 누르거나 방 코드 4자로 입장(기존과 같음).
- 방장: 시작(2명 이상), 방 설정(출제 순서, 라운드 수, 그리는 시간, 주제 켜고 끄기, 글자 수 표시), 방 대기에서 내보내기, 진행 중 "이 문제 넘기기"와 "이 판 끝내기".

**⑨ 예외**
- 동시 정답: 서버에 도착한 순서대로 처리한다. 먼저 도착한 사람이 첫 정답자(+20). 같은 사람이 정답을 또 쳐도 점수는 한 번.
- 맞힌 사람의 힌트 흘리기: 3-5절(정답 글은 숨김, 맞힌 뒤 채팅은 정답자끼리만).
- 정답 판정: 앞뒤 공백 제거 → 한글 정규화(NFC) → 띄어쓰기·가운뎃점 제거 → 영문 소문자 → 단어(`w`)나 다른 이름(`alt`)과 **완전히 같을 때만**. "짜장면인가"는 오답.
- 그리는 사람의 글·이모티콘·사진 이모티콘·사운드: 단어 고르기~그리기 동안 전부 거절("그림으로만 설명해 주세요"). 사진·사운드 이름으로 정답을 흘릴 수 있어서다.
- 단어는 **그리는 사람과 이미 맞힌 사람 기기에만** 보낸다. 나머지에게는 글자 수(켜져 있을 때)만. 정답 공개 때 모두에게 보낸다.
- 그림 데이터는 그리는 사람이 보낸 것만 받는다. 범위 밖 좌표·너무 많은 점·없는 색 번호는 버린다. 한 문제에 선 600개 또는 점 6만 개를 넘으면 "그림이 너무 많아요. 전체 지우기를 눌러 주세요".
- 채팅 속도: 맞히는 게임이라 기존 제한(1초 1개)은 너무 빡빡하다. 갱식마인드 방에서는 **1초 3개, 10초 15개, 1~40자**.
- 글자·숫자를 그려서 알려 주는 반칙: 기계로 못 잡는다. 화면에 "글자·숫자는 쓰지 않기"를 보여 주고, 방장이 "이 문제 넘기기"로 정리한다.
- 음성 통화로 정답을 말하는 것, 한 사람이 아이디 두 개로 들어오는 것: 친구끼리라 막지 않는다.
- 사용자 글자(이름·채팅·정답)는 화면에 `textContent`로만 넣는다. 그림은 캔버스에만 그린다(HTML로 넣지 않는다).
- 무작위(첫 출제자, 단어 3개)는 crypto 난수만.

**⑩ 기기·터치**
- 휴대폰 가로·PC·iPad. 누르는 곳은 휴대폰에서 최소 34px, PC 44px. 색 칸 28px 이상.
- 손가락·펜슬·마우스 모두 같은 방식(Pointer Events). 손바닥 대응은 6-3.
- `zoom` 속성 금지, `#ui`의 pointer-events 규칙 등 CLAUDE.md의 CSS 규칙을 따른다.
- iPad·Safari·펜슬 동작은 **미확인(실기기 확인 필요)**.

**⑪ 소리·움직임**

## 9. 서버 판정 원칙

- 규칙·시간·정답 판정은 전부 서버. 화면은 받은 상태를 그리기만 한다.
- **정답은 맞히기 전 사람에게 보내지 않는다.** `room.state.word`는 그리는 사람과 이미 맞힌 사람에게만, 나머지는 `null`. 정답 글과 정답자끼리의 채팅도 못 맞힌 사람에게 보내지 않는다. 정답 공개 단계에서만 모두에게.
  단어 후보 3개(`choices`)도 그리는 사람에게만. 이것을 지키는 시험 `test/draw/leaks.test.js`를 둔다(모든 단계·모든 사람 시점의 메시지에 단어가 없는지).
- 그림 선은 서버가 그대로 전달하되 형식·범위·양을 검사하고, 그 문제의 선 목록을 기억한다(재전송용). 문제가 끝나면 지운다.
- 갱식마인드 방에서 포커·라이어 전용 요청이 오면 `'지금은 할 수 없습니다.'`(죽지 않는다).

## 10. 통신 메시지 (제안. 확정되면 SPEC 7절에 먼저 적는다)

기존 `login`·`create`·`join`·`leave`·`start`·`chat`·`room`·`event`·`error`를 그대로 쓴다. 갱식마인드 전용 요청은 전부 **`{t:'dr', a: 종류, ...}`** 한 봉투.

화면 → 서버

| 메시지 | 필드 | 누가·언제 | 설명 |
|---|---|---|---|
| `create` | `mode:'draw'` | 로비 | 방 만들기. `DRAW=off`면 `'갱식마인드는 아직 열리지 않았습니다.'` |
| `start` | | 방장, 방 대기·최종 순위 | 시작 / 한 판 더 |

서버 → 화면

- `{t:'me', user, liar, draw:'off'|'test'|'on'}` — `me`에 `draw` 칸 하나 추가. 보이기 = `draw==='on' || (draw==='test' && 주소에 ?draw=1)`.
- `rooms` 목록 항목에 `mode:'draw'`, `max:8`.
- `room.state`(받는 사람 시점, `mode:'draw'`):

```js
{ code, mode:'draw', hostId, you,
  phase: 'lobby'|'pick'|'draw'|'reveal'|'final',
  settings: { order, rounds, time, len, topics },
  players: [{ id, name, seat, connected, score, hit }],        // hit = 이번 문제를 맞혔는가. 사진은 넣지 않는다(faces 알림으로 한 번)
  roundNo, q, qTotal,                 // 1라운드, 문제 5 / 14
  drawerId, endsAt,                   // 단계 끝 시각(epoch ms)
  mask: '□□□' | null,                 // 글자 수 칸(띄어쓰기 자리는 공백). 끄면 null
  word: null | '짜장면',              // 그리는 사람·이미 맞힌 사람, 또는 reveal 단계에서만
  choices: null | [{w, topic}],       // 그리는 사람, pick 단계에서만
  canUndo, canRedo,                   // 그리는 사람 버튼 흐리게 하기용
  reveal: null | { word, why: 'all'|'time'|'give'|'idle'|'skip'|'left',
                   gains: [{ id, pts, order }], drawerPts, nextId },
  ranking: null | [{ id, rank, score, correct }] }             // final 단계
```

  `{k:'drSync', ops:[{c,w,e,p} | {clear:1}], at:n, open:bool}`(들어오거나 다시 붙은 사람에게 한 일 목록 전부와 지금 위치, 한 번) ·
  `{k:'drHit', id, order}`("○○ 님 정답!" 알림. 점수는 정답 공개 때) · `chat`에 `sec:1`(정답자끼리 글 표시) · `faces`·`chat`·`chatLog`는 기존과 같음.
- 그림만은 예외로 `event`가 진짜 데이터다(상태에 그림을 넣으면 선 하나마다 방 상태 전체를 다시 보내야 한다). 놓쳤을 때는 재접속하면 `drSync`로 맞춘다.

전송량 어림: 그리는 한 사람이 초당 16개 × 받는 사람 7명 = 초당 약 110개의 작은 글. 그림 한 장은 보통 수십 KB. Render 무료 서버에 무리가 없다(추정, 실제 시험 필요).

## 11. 배포와 숨김 스위치

- 환경 변수 **`DRAW`**: `off`(기본. 화면·서버에 흔적 없음) / `test`(주소에 `?draw=1`이 있을 때만 로비 칸이 보임) / `on`(모두에게 보임).
  `render.yaml`은 `test`로 올리고, 사용자가 실기기에서 확인한 뒤 `on`. `test`는 숨김이지 잠금이 아니다(라이어와 같음).
- 화면 코드는 `import('./draw/index.js')`로 따로 불러온다(다른 게임만 하는 사람은 받지 않는다).
- Render 무료 한 대·Neon 그대로. 새 표 없음, 새 서비스 없음. 배포하면 서버가 다시 시작되어 진행 중인 방이 끊긴다(기존과 같음).
- 구역(제안): `shared/draw/`, `server/draw/`, `client/src/draw/`, `test/draw/`, `docs/draw/`, `design/draw/`.
- CSS 접두사 **`.dr-`**. 모듈별: 설정 `.dr-st-`, 상단·문제 띠 `.dr-hud-`, 플레이어 칸 `.dr-pl-`, 그림판 `.dr-cv-`, 색·도구 `.dr-tb-`, 정답 공개·순위 `.dr-rs-`.
- 시험: `npm run check`에 로비 칸·방 만들기 클릭, `npm test`에 한 판(`test/ui/draw-round.mjs`: 두 사람이 들어와 선을 긋고, 상대 화면에 선이 도착하고, 정답을 맞히고, 순위까지).

## 12. 완성 확인 시나리오

1. **한 판 끝까지**: 3명이 `?draw=1` 주소로 들어와 방을 만들고(순서대로, 2라운드) 시작한다. 그리는 사람에게만 단어 3개가 뜨고, 고르면 나머지 화면에는 `□□□`만 보인다. 그린 선이 나머지 화면에 1초 안에 같은 모양으로 나타난다. 한 명이 맞히면 "○○ 님 정답!"이 뜨고 시간이 30초로 줄며, 나머지 한 명도 맞히면 바로 정답 공개. 빨리 맞힌 사람 점수가 더 높고 그린 사람도 점수를 받는다. 6문제가 끝나면 최종 순위가 뜨고 "한 판 더"로 다시 시작된다.
2. **정답이 새지 않는다**: 그리는 동안 못 맞힌 사람의 기기가 받은 모든 메시지에 단어가 없다(자동 시험). 먼저 맞힌 사람이 채팅에 정답이나 힌트를 써도 못 맞힌 사람 화면에는 보이지 않는다. 그리는 사람이 채팅·이모티콘·사운드를 누르면 "그림으로만 설명해 주세요"가 뜬다.
3. **끊김과 늦게 들어오기**: 그리는 도중 맞히는 사람이 새로 고침하면 지금까지의 그림이 그대로 다시 보인다. 진행 중에 새 사람이 들어오면 지금 그림을 보고 다음 문제부터 맞힐 수 있다. 그리는 사람이 15초 넘게 끊기면 정답이 공개되고 다음 사람으로 넘어간다.
4. **휴대폰 가로·iPad**: 844×390 화면에서 그림판·색 12개·도구가 겹치지 않고 다 눌린다. iPad에서 펜슬로 그릴 때 손바닥을 대도 선이 생기지 않고, 손가락으로 색을 바꿀 수 있다. 빠르게 원을 그려도 각이 지지 않는다. (실기기 확인 필요)
5. **출제 순서 세 가지**: "맞힌 사람"으로 하면 가장 먼저 맞힌 사람이 다음에 그리고, 한 라운드 안에서 같은 사람이 두 번 그리지 않는다. "랜덤"으로 하면 순서가 매번 다르지만 모두 한 번씩 그린 뒤에야 다음 라운드가 된다. 되돌리기를 세 번 누르고 다시 하기를 두 번 누르면 모든 사람 화면이 같은 그림이다.
6. **숨김 스위치**: `DRAW=off`면 로비와 서버 어디에도 갱식마인드가 없다. `test`면 `?draw=1` 주소에서만 칸이 보인다. 포커·블러핑·라이어는 전과 똑같이 돌아간다(`npm test` 통과).

## 13. 미정 ⬜ (사용자 확인 필요)

확정된 것: 이름(갱식마인드), 단어 3개 중 고르기, 출제 순서 3가지 + 라운드 수 따로, 여러 명이 맞힐 때까지 + 빠를수록 높은 점수, 채우기 빼고 시작, 되돌리기·다시 하기.

1. 점수 수치(40 + 60×남은 비율, 첫 정답 +20, 그린 사람 100×비율)는 기본안. 해 보고 조절.
2. 첫 정답 뒤 남은 시간을 30초로 줄이는 것(기본안: 줄인다).
3. "맞힌 사람"·"랜덤"에서도 한 라운드에 한 사람이 한 번만 그리는 것(기본안: 그렇다).
4. 맞힌 사람의 채팅을 정답자끼리만 보이게 하는 것(기본안: 그렇다).
