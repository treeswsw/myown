# 갱식마인드 기획서 (GDD) — v1.0 확정판

갱식 클럽 안의 네 번째 게임. 한 사람이 단어를 그림으로 그리고 나머지가 채팅으로 맞힌다.
표시: ✅ 사용자가 정함 · ☑ 기본안(사용자가 정하지 않아 기획이 정함. 바꿀 수 있음) · ⬜ 미정. 확정 상태는 13절.
시안: `design/draw/index.html`(정적, 가짜 데이터) · 스크린샷 `design/draw/shots/`.
이 문서가 구현의 기준이다(통신은 10절, 모듈 나누기는 11-1절). 코드는 아직 없다. 3D·소리·실기기 느낌(iPad·Safari·펜슬)은 전부 **미확인(실기기 확인 필요)**.

## 1. 한 줄 소개와 이름

친구 2~8명이 각자 기기로 방에 모여, 돌아가며 한 명이 단어를 그리고 나머지가 채팅으로 맞히는 그림 퀴즈.

- ✅ 이름: **갱식마인드**(사용자 확정 2026-11-13).
  - 코드에서는 이름을 **한 곳**에만 적는다: `shared/draw/name.js`의 `GAME_NAME`. 화면·오류 문구는 전부 이 값을 쓴다(나중에 바꾸기 쉽게). 시안도 `index.html` 맨 위 `GAME_NAME` 하나다.
- "캐치마인드"는 넷마블의 게임 이름이다. **이름·로고·캐릭터·그림·화면 꾸밈은 쓰지 않는다.** 규칙의 흐름과 배치(좌우 플레이어 칸, 가운데 그림판)만 참고했다.
  그림판 참고 이미지(사용자 제공)의 상표·스프링 노트 꾸밈도 쓰지 않는다.

## 2. 뼈대

- ✅ 갱식 클럽과 같은 사이트·같은 아이디·같은 프로필 사진·같은 로비. 설치 없는 웹.
- ✅ 라이어게임과 같은 **숨김 스위치**로 공개한다(11절).
- ✅ 규칙은 원작과 같게. 웹이라서 바꾼 것은 3-2절에 이유와 함께 모았다.
- ✅ 기기: 휴대폰 가로, PC, iPad(손가락·펜슬·마우스). 세로로 들면 기존 "가로로 돌려 주세요" 안내.
- ☑ **3D 장면을 쓰지 않는다.** 평면 화면만(그림 그리기가 끊기지 않게 하고 배터리를 아낀다). 배경은 어두운 클럽 톤, 그림판만 밝은 종이.
- ☑ 인원 2~8명(원작 8명 이하). 2명이면 서로 번갈아 그린다.
- ☑ 채팅·이모티콘·사운드는 사이트의 것을 그대로 쓰되, 그리는 사람은 그리는 동안 전부 막는다(9절 유출 방지).

## 3. 규칙

### 3-1. 원작 규칙 (조사 결과)

출처는 14절. 나무위키 등은 이 환경에서 직접 열 수 없어 검색 요약으로 확인했다. "확인 못 함"은 그대로 적었다.

| 항목 | 원작(PC판) | 확인 |
|---|---|---|
| 인원 | 8명 이하 | 확인 |
| 출제 순서 | 방에 있는 사람이 한 명씩 돌아가며 출제(정답자가 다음 출제자가 되는 방식 아님) | 확인 |
| 단어 | 문제 은행에서 한 단어를 준다(고르지 않음). 출제자에게만 보인다 | 확인(화면 "문제" 칸) |
| 시간 | 문제당 2분 20초 | 확인 |
| 문제 수 | 한 판 20라운드 | 확인 |
| 무입력 넘김 | 20초 동안 그림판을 누르지 않으면 자동으로 넘어간다 | 확인 |
| 정답 | 채팅으로 입력. 가장 먼저 맞힌 사람이 정답자 | 확인 |
| 한 문제의 끝 | 정답자가 한 명 나오면 그 문제가 끝난다 | **확인 못 함**(기억과 화면의 "정답 N" 표시로 추정) |
| 점수 | 화면에는 사람마다 "정답 N". 최근 판은 출제자와 정답자가 함께 점수를 얻고 빨리 맞힐수록 높다 | 확인 |
| 포기 | 출제자에게 "포기" 버튼이 있다 | 버튼은 확인, 처리 방식은 확인 못 함 |
| 힌트 | 공식 힌트 없음. 출제자가 구석에 점으로 글자 수를 알려 주는 관행 | 확인 |
| 금지 | 글자·숫자를 쓰면 안 된다. 출제자는 채팅 불가("그림으로만 설명해 주세요") | 확인 |
| 그림 도구 | 색 5가지(검정·빨강·파랑·초록·노랑), 지우개, 전체 지우기 | 확인(화면) |

### 3-2. 우리 규칙 = 원작 그대로 + 웹에서 바꾼 것

그대로 가져오는 것: 출제자만 단어를 봄, 채팅으로 맞히기, 2분 20초, 포기 버튼, 무입력 20초 넘김, 글자·숫자 금지, 출제자 채팅 금지,
출제자와 정답자가 함께 점수를 얻고 빨리 맞힐수록 높음(원작 최근 판).

바꾼 것(✅ 사용자 결정, ☑ 기본안):

| # | 바꾼 것 | 이유 |
|---|---|---|
| 1 | ✅ **출제 순서를 방장이 고른다**: 순서대로 / 맞힌 사람 / 랜덤 (3-3) | 사용자 결정 |
| 2 | ✅ **라운드 수를 따로 고른다**(1·**2**·3·5). 한 라운드 = 모두 한 번씩 그리기. 원작은 20문제 고정 | 사용자 결정. 인원이 달라도 그리는 횟수가 같다 |
| 3 | ✅ 단어 **3개 중 고르기**(10초, 안 고르면 첫 단어). 원작은 자동 1개 | 단어 목록이 라이어게임용이라 그리기 힘든 단어가 섞여 있다 |
| 4 | ✅ **여러 명이 맞힐 때까지 계속**, 빠를수록 높은 점수(3-4). 화면의 "정답 N"은 "N점"으로 | 사용자 결정 |
| 5 | ☑ 맞힌 사람의 채팅은 **맞힌 사람과 그리는 사람에게만** 보인다(3-5) | 먼저 맞힌 사람이 힌트를 흘리지 못하게 |
| 6 | ☑ 글자 수를 칸으로 자동 표시(`□□□ 3글자`), 방장이 끌 수 있다 | 원작도 점을 찍어 알려 주던 관행 |
| 7 | ☑ 무입력 넘김은 **시작 후 20초 안에 첫 선이 없을 때만** | 생각하느라 멈춘 사람은 넘기지 않는다 |
| 8 | ✅ 그림 도구: 12색, 굵기 빠른 버튼 3개 + 굵기 조정, 정밀 지우개·획 지우개, 되돌리기·다시 하기 | 6절 |
| 9 | ☑ 정답 판정: 띄어쓰기·대소문자 무시, 단어 목록의 "다른 이름"도 정답 | 입력 실수로 틀리는 일을 막는다 |
| 10 | ☑ 방장 메뉴에 "이 문제 넘기기" | 글자를 써서 알려 주는 반칙은 기계가 못 잡는다 |

### 3-3. 출제 순서와 라운드 (✅ 사용자: 순서대로 / 맞힌 사람이 그리기 / 랜덤, 라운드 수는 따로)

**라운드의 뜻은 세 방식 모두 같다: 한 라운드 = 방에 있는 사람이 모두 한 번씩 그린다.**
문제 수 = 인원 × 라운드 수(예: 5명 × 2라운드 = 10문제). 라운드 수 선택지 1·**2**·3·5(☑ 기본 2).
한 라운드 안에서는 **한 사람이 한 번만** 그린다 — 이것이 "한 사람이 계속 그리는 일"을 막는 장치다(☑).

| 방식 | 다음에 그리는 사람 |
|---|---|
| **순서대로**(☑ 기본) | 자리 순서(들어온 순서). 판의 첫 출제자만 무작위 |
| **맞힌 사람** | 방금 문제를 **가장 먼저 맞힌 사람**. 그 사람이 이번 라운드에 이미 그렸으면 그다음으로 빨리 맞힌 사람. 맞힌 사람 중에 아직 안 그린 사람이 없거나 아무도 못 맞혔으면, 아직 안 그린 사람 중 자리 순서로 다음 사람. 판의 첫 출제자는 무작위 |
| **랜덤** | 이번 라운드에 아직 안 그린 사람 중에서 매 문제 무작위(crypto 난수). 라운드가 바뀔 때 방금 그린 사람이 곧바로 또 뽑히지는 않는다(2명일 때 제외) |

- 모두 한 번씩 그리면 다음 라운드. "이미 그림" 기록을 비운다.
- 도중에 들어온 사람은 **다음 라운드부터** 그리는 순서에 들어간다(맞히기는 다음 문제부터 바로). 한 라운드의 문제 수는 그 라운드를 시작할 때의 인원이다.
- 끊겼거나 나간 사람 차례는 건너뛴다(그 라운드에 그린 것으로 친다).
- ☑ "맞힌 사람" 방식을 "제한 없이 맞힌 사람이 계속 그리기"로 하지 않은 이유: 잘 맞히는 두 사람만 번갈아 그리고 나머지는 한 번도 못 그릴 수 있다.

### 3-4. 한 문제의 끝과 점수 (✅ 사용자: "여러 명이 맞힐 때까지, 빠를수록 높은 점수")

- 한 문제는 **시간이 끝나거나, 그리는 사람을 뺀 모두(접속 중인 사람)가 맞히면** 끝난다. 그 밖에 포기·넘김·그리는 사람 나감.
- ✅ 첫 정답이 나왔을 때 남은 시간이 30초보다 길면 **30초로 줄인다**(기다리는 시간이 길어지지 않게. 화면에 "30초 남았어요").
- ✅ 맞힌 사람 점수 = **40 + 60 × (맞힌 순간 남은 시간 ÷ 그리는 시간)**, 소수점 반올림. **첫 정답자는 +20.**
  - 예(2분 20초, 5명이 맞히는 중): 18초에 첫 정답 → 40 + 52 + 20 = **112점**. 시간이 30초로 줄고, 25초 남기고 맞히면 40 + 11 = **51점**, 14초 남기고 맞히면 **46점**.
  - 한 문제에서 맞힌 사람은 최소 40점, 최대 120점.
- ✅ 그린 사람 점수 = **100 × (맞힌 사람 수 ÷ 맞힐 수 있던 사람 수)**, 반올림. 예: 5명 중 3명 → 60점. 모두 맞히면 100점.
- 아무도 못 맞히면 모두 0점. 포기·넘김·나감이면 그린 사람은 0점, 이미 맞힌 사람의 점수는 그대로.
- 순위: 점수 큰 순 → 맞힌 횟수 큰 순 → 같으면 공동 순위.

### 3-5. 맞힌 뒤의 채팅 (☑ 힌트 흘리기 방지)

- 정답 글 자체는 **아무에게도 채팅으로 보이지 않는다.** 모두에게 "민수 님 정답!" 알림만 뜨고, 그 사람 칸이 초록색 "맞힘"으로 바뀐다.
- 맞힌 사람이 그 뒤에 쓰는 글은 **이미 맞힌 사람들과 그리는 사람에게만** 보인다(초록 글씨 "정답자끼리"). 아직 못 맞힌 사람에게는 보내지 않는다.
- 맞힌 사람의 사진 이모티콘·사운드는 정답 공개 전까지 막는다(그림·이름으로 흘릴 수 있다). 기본 이모티콘 6개는 된다.
- 아직 못 맞힌 사람의 글은 모두에게 보인다(오답 구경이 재미).
- 맞힌 사람 화면에는 그때부터 단어가 보인다(`□□□` 대신 `짜장면`).
- 다시 들어온 사람에게 주는 채팅 기록에도 같은 규칙을 적용한다(못 맞힌 사람에게 정답자끼리 한 글을 주지 않는다).

## 4. 한 판의 진행

```
방 대기 → [단어 고르기 10초 → 그리기 2분 20초 → 정답 공개 5초] × (인원 × 라운드 수) → 최종 순위 → 방 대기(또는 한 판 더)
```

| 단계 | 무슨 일 | 끝 조건 | 시간 |
|---|---|---|---|
| 방 대기 `lobby` | 방장이 설정(출제 순서, 라운드 수, 그리는 시간, 주제)을 고르고 시작. 2명 이상 | 방장 "시작" | 없음 |
| 단어 고르기 `pick` | 그리는 사람에게 단어 3개(주제 표시). 나머지는 "○○ 님이 고르는 중" | 고름 / 10초 지나면 첫 단어 | 10초 |
| 그리기 `draw` | 그리는 사람: 단어·도구·포기. 나머지: 글자 수 칸·정답 입력. 맞힌 사람은 "맞힘" 표시 | ① **모두 맞힘** ② 시간 끝(첫 정답 뒤에는 최대 30초) ③ 포기 ④ 20초 안에 첫 선 없음 ⑤ 방장이 넘김 ⑥ 그리는 사람이 나감 | 2분 20초(60초·90초·**2분 20초** 중 방장 선택) |
| 정답 공개 `reveal` | 그림은 그대로 두고 정답, 맞힌 사람과 얻은 점수, 그린 사람 점수. 아무도 못 맞혔으면 "시간 끝! 정답은 ○○" | 자동 | 5초(건너뛰기 없음) |
| 최종 순위 `final` | 1~3등 단상 + 나머지 목록(점수, 맞힌 횟수) | 방장 "한 판 더" 또는 "방으로" | 없음(방장이 누를 때까지) |

- 출제 순서는 3-3. 판의 첫 출제자는 무작위(crypto 난수).
- 한 방에서 이미 나온 단어는 그 방에서 다시 나오지 않는다(보여 준 3개 중 안 고른 것은 다시 나올 수 있다).
- 시간은 서버가 잰다. 화면은 서버가 준 끝 시각(`endsAt`)으로 줄어드는 막대와 숫자만 그린다.

## 5. 단어

- `server/liar/words.json`을 **읽기만 해서 재사용할 수 있다**(확인함). 구조: `sets.mine.topics[]`(11주제 × 100개 = 1,100개), 단어마다 `w`(단어)와 `alt`(다른 이름, 120개 단어에 있음). 가장 긴 단어 12자.
  - 라이어 폴더는 gamemine 과 같게 유지해야 하므로 **파일을 고치거나 옮기지 않는다.** 갱식마인드 서버가 같은 파일을 불러 쓴다.
  - `alt`는 정답 판정의 "다른 이름"으로 그대로 쓴다.
- ☑ 기본으로 쓰는 주제 8개(800개): 음식, 동물, 직업, 장소, 스포츠, 물건, 취미, 탈것.
- ☑ 기본으로 끄는 주제 3개: 영화·만화, 나라·도시, 인물 — 그림으로 설명하기 어렵고 글자를 쓰고 싶어진다. 방장이 방 설정에서 켤 수 있다.
- ☑ 스타 버전 묶음(`sets.star`)은 1차에서 쓰지 않는다(연예인·브랜드·롤챔프는 그리기 어렵다).
- ☑ 그림용으로 단어를 따로 고르는 일(너무 어려운 단어 빼기)은 실제로 해 본 뒤 결정. 필요하면 `docs/draw/WORDS.md`에 "빼는 단어" 목록만 둔다(원본은 그대로).

### 6-2. 결정 (✅ 사용자: "직관적으로 딱 필요한 기능만", ☑ 세부)

지우개 두 가지의 배치(☑): **버튼 두 개를 나란히** 둔다(길게 누르기·두 번 누르기로 바꾸는 방식은 쓰지 않는다 — 숨은 조작은 처음 보는 사람이 못 찾는다).
아이콘: 정밀 지우개 = 지우개 그림, 획 지우개 = 구불구불한 선에 사선을 그은 그림. PC에는 아래에 글자("정밀 지우개", "획 지우개")도 붙는다.
- 획 지우개로 한 번 문질러(누르고 떼기 전까지) 지운 선들은 **되돌리기 한 번에 함께** 돌아온다.
- 획 지우개로 지운 선 밑에 정밀 지우개 자국이 있었다면 자국은 그대로 남는다(종이 색이라 보이지 않는다).

#### 6-2-1. 굵기 조정 (✅ 사용자: "조정하는 버튼 따로 하나 … 세밀하게")

- 빠른 버튼 3개 옆의 **굵기 조정 버튼**(막대 두 줄 그림)을 누르면 작은 창이 뜬다: **미리보기 동그라미**(지금 색·실제 굵기) + **숫자** + **막대** + **−/+ 버튼**(1씩).
- 범위 **2~40px, 1px 단위**(800×600 기준). 막대 손잡이 28px, −/+ 버튼 36px(손가락용).
- **펜과 정밀 지우개는 굵기를 따로 기억한다**(☑ 펜 처음 10, 정밀 지우개 처음 24). 이유: 지우개는 보통 더 굵게 쓰는데, 지우개를 쓰고 돌아왔을 때 펜 굵기가 바뀌어 있으면 안 된다.
- 빠른 버튼 값(4·10·24)과 같으면 그 버튼이 켜진 것으로 보이고, 다른 값이면 조정 버튼이 켜진 것으로 보인다.
- 창 위치 — **그림판을 가리지 않는다**: PC·iPad는 그림판 아래 줄 안에서 옆으로 펼쳐진다. 휴대폰 가로는 왼쪽 아래(플레이어 목록 위)에 뜬다.
- 바깥을 누르거나 그리기 시작하면 닫힌다. PC 단축키 `[` `]`로 1씩 줄이고 늘린다(창을 열지 않아도 됨).

되돌리기·다시 하기 규칙:
- 그 문제의 "한 일 목록"(선, 정밀 지우개 자국, 획 지우개로 지운 묶음, 전체 지우기)과 "지금 위치"를 서버가 기억한다. 되돌리기는 위치를 한 칸 뒤로, 다시 하기는 한 칸 앞으로.
- **새 선을 긋거나 전체 지우기를 하면 다시 하기 목록은 비워진다**(되돌린 것은 사라진다).
- 전체 지우기도 한 일 하나다. 되돌리면 그림이 통째로 돌아오고, 다시 하면 또 지워진다.
- 횟수 제한은 따로 없다(한 문제의 선은 최대 600개). 문제가 바뀌면 목록을 비운다.
- 다른 사람 화면에도 같은 순서로 전달한다(`drUndo`, `drRedo`). 받는 쪽도 같은 목록과 위치를 갖고 다시 그린다.

단축키(PC, 그리는 사람만. 그리는 사람은 채팅을 못 쓰니 글자 키와 겹치지 않는다): `B` 펜 · `E` 정밀 지우개 · `Shift+E` 획 지우개 · `1` `2` `3` 빠른 굵기 · `[` `]` 굵기 1씩 · `Ctrl/⌘+Z` 되돌리기 · `Ctrl/⌘+Shift+Z` 또는 `Ctrl+Y` 다시 하기. 전체 지우기와 포기는 단축키 없음(실수 방지).

### 6-3. 선 부드러움 (✅ 사용자: "부드럽게 그림이 그려지게")

수치는 시작값이다. 느낌은 **미확인(실기기 확인 필요)** — 사용자가 iPad·휴대폰에서 그려 보고 조절한다.

| 항목 | 기준 |
|---|---|
| 좌표 | 그림판은 항상 4:3, 내부 좌표 **1600×1200**(= 800×600의 반 픽셀 단위 정수). 화면 크기가 달라도 모두 같은 그림을 본다 |
| 입력 | Pointer Events 하나로 마우스·손가락·펜을 받는다. `pointermove`마다 `getCoalescedEvents()`로 **브라우저가 묶어 버린 중간 점까지 전부** 쓴다(없으면 마지막 점만) |
| 점 간격 | 앞 점과 **2px(800 기준) 미만**이면 버린다. 한 번 누르고 떼기만 하면 점 하나(동그라미)로 그린다 |
| 떨림 줄이기 | 새 점 = 앞 점 35% + 손 위치 65%(가벼운 보정). 펜슬은 보정 없음(100%). ☑ 값은 실기기에서 조절 |
| 곡선 | 점과 점을 직선으로 잇지 않는다. **가운뎃점 2차 베지어**: 이웃한 두 점의 가운뎃점에서 다음 가운뎃점까지, 실제 점을 조절점으로 `quadraticCurveTo`. 각이 지지 않는다 |
| 선 끝·이음 | `lineCap = 'round'`, `lineJoin = 'round'` |
| 선명함 | 캔버스 실제 크기 = 보이는 크기 × `devicePixelRatio`(최대 2). 화면 크기가 바뀌면 저장된 선으로 다시 그린다(그림이 흐려지거나 사라지지 않는다) |
| 내 화면 | **누르는 즉시 내 화면에 먼저 그린다**(서버 답을 기다리지 않는다). 입력 처리 안에서 바로 그리고, 캔버스는 `desynchronized: true` 힌트 |
| 보내기 | 점을 모아 **60ms마다 한 번**(초당 약 16번. 연결당 초당 20개 제한 안쪽). 한 번에 최대 64점 |
| 받는 쪽 | 받은 점을 **같은 곡선 방식**으로 그린다. 한 묶음을 한꺼번에 찍지 않고 다음 화면 갱신 2~3번에 나눠 이어 그려 뚝뚝 끊겨 보이지 않게 한다 |
| 되돌리기·다시 하기 | 한 일 목록의 지금 위치까지 다시 그린다. 선 20개마다 중간 그림을 저장해 빨리 다시 그린다 |
| 손바닥 | ① 그림판은 `touch-action: none`(화면이 밀리거나 확대되지 않음) ② **먼저 닿은 한 점만** 그린다(나중에 닿은 손바닥·둘째 손가락 무시) ③ **펜슬이 한 번이라도 닿으면 그 뒤로 그림판은 펜만 받는다**(손가락·손바닥은 그리지 않음. 버튼은 손가락으로 누를 수 있다. 방을 나가면 풀림) ④ 브라우저가 "손바닥이었다"고 알려 주면(`pointercancel`) 그 선을 통째로 취소한다 ⑤ 닿은 면이 60px보다 넓으면 무시(알려 주는 기기만) |
| 그 밖 | 그림판에서 길게 누르기 메뉴·글자 선택·두 번 눌러 확대를 막는다. 그리는 중에 손이 그림판 밖으로 나가도 선이 끊기지 않는다(`setPointerCapture`) |

- 휴대폰 키보드: 가로 화면에서 키보드가 절반을 가린다. 입력 칸을 맨 위에 두고, 키보드가 올라오면 보이는 높이에 맞춰 그림판을 줄인다(`visualViewport`). **미확인(실기기 확인 필요)**.
- **말풍선**(✅ 사용자: "옆으로 튀어나가도 재밌을 것 같다"): 채팅은 플레이어 칸 **옆으로 꼬리 달린 말풍선**이 튀어나온다. 왼쪽 칸은 오른쪽(그림판 쪽)으로, 오른쪽 칸은 왼쪽으로.
  - 표시 시간 **3.5초** 뒤 흐려지며 사라진다. 같은 사람이 새로 말하면 바로 **교체**한다.
  - 최대 폭 170px, **두 줄**까지 줄바꿈, 넘으면 `…`. 휴대폰은 한 줄·최대 124px.
  - 그림을 가리지 않게: 말풍선은 칸과 그림판 사이의 빈 자리에 뜨고, 길면 **그림판 가장자리에 조금 겹친다**(왼쪽·오른쪽 끝은 그림이 드문 자리). 약간 비치게(95%) 하고 **누를 수 없게** 한다(밑의 색·도구가 그대로 눌린다).
    ✅ **그리는 사람 화면(PC·iPad)에서는 말풍선을 프로필 위쪽으로 띄운다**(꼬리가 아래). 색·도구 칸과 그림판을 가리지 않는다. 폭 최대 118px.
  - 정답을 맞힌 말: 글자는 보이지 않고 **초록 말풍선 "정답!"** 만 뜬다. 맞힌 사람끼리 하는 말: 맞힌 사람·그리는 사람에게는 초록 테두리 말풍선으로 글이 보이고, 못 맞힌 사람에게는 **아무것도 뜨지 않는다**(글이 전송되지 않는다).
  - 휴대폰 가로: 맞히는 사람은 왼쪽 목록의 줄 옆으로 말풍선이 튀어나와 그림판 왼쪽 끝에 겹친다(오른쪽 채팅 기록도 그대로). 그리는 사람은 그림판·색을 가리지 않게 **그 줄 안**(점수 자리)에 잠깐 뜬다.
  - 움직임: 말풍선은 꼬리 쪽에서 톡 커지며 나타난다(0.28초).
- **말할 때 프로필이 통통 튄다**(✅ 사용자): 채팅 말풍선이 뜰 때마다 그 사람 프로필이 위로 12px 튀었다가 내려오며 살짝 눌렸다 펴진다(**0.38초**).
  - **정답을 맞혔을 때**는 더 큰 움직임: 24px 높이로 두 번 뛰며 좌우로 살짝 기울고 1.18배까지 커졌다 돌아온다(**0.75초**) + 초록 테두리가 켜진다.
  - 휴대폰 가로 목록의 작은 프로필(28px)도 같은 움직임을 쓴다.
  - `prefers-reduced-motion`이면 튀지 않고 말풍선·테두리만 바뀐다. 움직임 느낌은 **미확인(실기기 확인 필요)**.
  - 시안에서 직접 볼 수 있다: `?s=guess`나 `?s=draw` 화면 왼쪽 아래 "▶ 말하기 시연", "▶ 정답 시연".
- 상단 줄은 라이어게임의 `.lgbar`와 같은 자리·방식(방 코드, 메뉴, 소리, 나가기).

## 9. 서버 판정 원칙

- 규칙·시간·정답 판정은 전부 서버. 화면은 받은 상태를 그리기만 한다.
- **정답은 맞히기 전 사람에게 보내지 않는다.** `room.state.word`는 그리는 사람과 이미 맞힌 사람에게만, 나머지는 `null`. 정답 글과 정답자끼리의 채팅도 못 맞힌 사람에게 보내지 않는다. 정답 공개 단계에서만 모두에게.
  단어 후보 3개(`choices`)도 그리는 사람에게만. 이것을 지키는 시험 `test/draw/leaks.test.js`를 둔다(모든 단계·모든 사람 시점의 메시지에 단어가 없는지).
- 그림 선은 서버가 그대로 전달하되 형식·범위·양을 검사하고, 그 문제의 선 목록을 기억한다(재전송용). 문제가 끝나면 지운다.

## 10. 통신 메시지 (✅ 확정. 서버와 화면은 이 절만 보고 따로 만든다. 바꾸려면 이 절을 먼저 고친다)

WebSocket `/ws`, JSON, `{t: 종류, ...}`. 기존 SPEC 7절을 그대로 쓰고 갱식마인드에 필요한 것만 더한다.
갱식마인드 전용 요청은 전부 **`{t:'dr', a: 종류, ...}`** 한 봉투. `protocol.js`는 봉투(`t:'dr'`, `a`는 글자 1~20자)만 보고, 속은 `shared/draw/protocol.js`가 검사한다.
방은 `mode:'draw'`. 서버가 모든 규칙과 시간을 판정한다. 화면의 진짜 상태는 항상 `room.state`이고, **그림만 예외로 `event`가 진짜 데이터**다(10-5).

### 10-1. 공통 값

| 이름 | 값 |
|---|---|
| 좌표 | 정수. x `0..1600`, y `0..1200`(= 800×600의 반 픽셀 단위) |
| 색 `c` | 정수 `0..11`(6-2 색 표의 순서 − 1) |
| 굵기 `w` | 정수 `2..40`(800×600 기준 px) |
| 점 배열 `p` | 정수 배열. **선의 첫 메시지(`st`)** 는 `[x0, y0, dx1, dy1, dx2, dy2, ...]`, **이어지는 메시지(`pt`)** 는 `[dx, dy, ...]`(바로 앞 점과의 차이). 길이는 짝수, 한 메시지에 최대 128개 숫자(64점), 차이값은 `-1600..1600` |
| 한 일(op) | `{c, w, e, p}`(선. `e:0` 펜, `e:1` 정밀 지우개. `p`는 `st`와 `pt`를 이어 붙인 것) · `{rm:[선 번호...]}`(획 지우개 한 묶음) · `{clear:1}`(전체 지우기) |
| 선 번호 | 그 한 일이 목록 `ops`에서 차지하는 **자리 번호**(0부터). 서버와 모든 화면이 같은 순서로 세므로 따로 보내지 않는다 |
| 위치 `at` | 지금 화면에 반영된 한 일의 개수. `ops[0..at)`만 그려진 것이다. 되돌리기 `at-1`, 다시 하기 `at+1` |
| 한도 | 한 문제에 한 일 600개, 점 60,000개, 선 하나에 점 4,000개 |

한 일 목록 규칙(서버와 화면이 똑같이 적용, `shared/draw/ops.js` 하나를 함께 쓴다):
- 새 한 일(`st`·`rm`·`clear`)이 오면 `ops`를 `at`까지만 남기고(다시 하기 목록 버림) 뒤에 붙인 뒤 `at = ops.length`.
- `rm`에 `g:1`이 있고 `ops`의 마지막이 `rm`이며 `at === ops.length`이면 새로 붙이지 않고 그 `rm`의 번호 목록에 더한다.
- 그리기: `ops[0..at)`을 순서대로. 선은 그리고, `clear`는 종이를 비우고, `rm`에 든 번호의 선은 처음부터 없던 것으로 친다.
- `rm`의 번호는 `at`보다 작고, 펜 선(`e:0`)이고, 이미 지워지지 않은 것만 받는다.
- 누적 좌표 검사: 점 배열은 차이값이라 한 메시지만 봐서는 x `0..1600`, y `0..1200` 안인지 알 수 없다. `shared/draw/ops.js`가 긋는 중인 선의 **마지막 점을 기억**해 더하면서 검사한다. 넘으면 그 요청을 버리고(오류 글 없음) 보낸 사람에게 `drSync`를 보낸다.
- `pt`는 `f:1`(선 끝)일 때만 `p:[]`(빈 배열)를 허용한다. `f`가 없는 `pt`의 `p`는 비어 있으면 형식 오류.
- `rm.ids`에 같은 번호가 두 번 이상 있으면 요청 전체를 형식 오류로 본다. 다른 그림 요청처럼 오류 글 없이 버리고, 보낸 사람에게 `drSync`를 보낸다.
- 시간 상수 이름은 `shared/draw/constants.js`의 `TIMES{pick, reveal, rush, idle, drawerAway, seatKeep}`를 따른다: `pick` 단어 고르기 10초 · `reveal` 정답 공개 5초 · `rush` 첫 정답 뒤 남은 시간 상한 30초 · `idle` 시작 후 첫 선이 없으면 넘기는 20초 · `drawerAway` 그리는 사람 끊김 대기 15초 · `seatKeep` 맞히는 사람 끊김 자리 유지 60초(기존 규칙). 그리는 시간은 `TIME_CHOICES`(60·90·140).

### 10-2. 화면 → 서버

기존 메시지: `login`, `avatar`, `join{code}`, `leave`, `emote`, `pemote`, `snd…`는 그대로.

| 메시지 | 필드(타입) | 누가·언제 | 결과 |
|---|---|---|---|
| `create` | `mode:'draw'` | 로비 | 방 생성. 스위치가 꺼져 있으면 `dr_off` |
| `start` | — | 방장, `lobby`·`final` | 새 판. 접속 중 2명 미만이면 `dr_need2`, 켜진 주제가 없으면 `dr_topics` |
| `chat` | `text: string`(1~40자) | 10-6 표 | 정답 판정을 겸한다 |
| `dr` `settings` | `order?: 'seq'\|'hit'\|'rand'`, `rounds?: 1\|2\|3\|5`, `time?: 60\|90\|140`, `len?: boolean`, `topics?: string[]`(주제 이름, 1개 이상) | 방장, `lobby`·`final` | 보낸 칸만 바뀐다. 값이 틀리면 `dr_bad` |
| `dr` `kick` | `id: string` | 방장, `lobby`·`final` | 내보냄(그 사람에게 `room:null` + `error dr_kicked`) |
| `dr` `pick` | `i: 0\|1\|2` | 그리는 사람, `pick` | 단어 확정 → `draw` |
| `dr` `st` | `c`, `w`, `e: 0\|1`, `p`(첫 메시지 모양) | 그리는 사람, `draw` | 새 선 시작. 앞 선이 안 끝났으면 끝난 것으로 친다 |
| `dr` `pt` | `p`(이어지는 모양), `f?: 1` | 〃, 긋는 중인 선이 있을 때 | 점 추가. `f:1`이면 선 끝. 60ms마다 한 번 |
| `dr` `cx` | — | 〃, 긋는 중 | 긋던 선을 없던 것으로(손바닥). 되돌리기 목록에 남지 않는다 |
| `dr` `rm` | `ids: number[]`(1~50개), `g?: 1` | 〃, `draw` | 획 지우개 |
| `dr` `undo` | — | 〃 | `at > 0`이면 `at-1`. 아니면 무시 |
| `dr` `redo` | — | 〃 | `at < ops.length`이면 `at+1`. 아니면 무시 |
| `dr` `clear` | — | 〃 | 전체 지우기(종이가 이미 비어 있으면 무시) |
| `dr` `give` | — | 〃 | 포기 → `reveal`(`why:'give'`) |
| `dr` `skip` | — | 방장, `pick`·`draw` | 이 문제 넘기기 → `reveal`(`why:'skip'`) |
| `dr` `end` | — | 방장, `pick`·`draw`·`reveal` | 이 판 끝내기 → `lobby`(점수 저장 안 함) |

- `settings` 규칙: `topics`는 주제 이름 1~20자, 1~30개, 중복은 서버가 지운다. 없는 주제 이름은 무시하고, 남는 주제가 하나도 없으면 `dr_bad`. 고칠 칸(`order`·`rounds`·`time`·`len`·`topics`)이 하나도 없는 `settings`도 `dr_bad`.
- 그림 요청(`st`·`pt`·`cx`·`rm`·`undo`·`redo`·`clear`)이 틀렸을 때(범위 밖, 한도 초과가 아닌 형식 오류, 그리는 사람이 아님, 단계가 다름)는 **오류 글 없이 버린다.** 보낸 사람이 그리는 사람이면 `drSync`를 다시 보내 화면을 서버와 맞춘다.
- 한도를 넘으면 `dr_canvas_full`을 그리는 사람에게 보내고 그 선은 버린다.
- 다른 방(포커·라이어)에서 `dr`이 오면 `'알 수 없는 요청입니다.'`. 갱식마인드 방에서 `mode`·`act`·`play`·`liar`·`lg`가 오면 `dr_now`.

### 10-4. `room.state` (받는 사람 시점, `mode:'draw'`)

```js
{
  code: 'KQZT', mode: 'draw', hostId: 'gangsik', you: 'jiho',
  phase: 'lobby' | 'pick' | 'draw' | 'reveal' | 'final',
  settings: { order: 'seq'|'hit'|'rand', rounds: 1|2|3|5, time: 60|90|140, len: true|false,
              topics: ['음식', ...],            // 켜진 주제
              allTopics: ['음식', ...] },       // 고를 수 있는 주제 전부(11개)
  players: [{ id, name, seat,                   // seat = 자리 번호 0..7(들어온 순서, 빈 번호 채움)
              connected: bool,
              score: number,                    // 이번 판 점수
              correct: number,                  // 이번 판에 맞힌 횟수
              hit: bool,                        // 이번 문제를 맞혔는가(pick·draw 동안. 그 밖에는 false)
              drew: bool }],                    // 이번 라운드에 이미 그렸는가
  roundNo: 1, q: 5, qTotal: 14,                 // lobby 에서는 0, 0, 0
  drawerId: id | null,                          // pick·draw·reveal 동안
  endsAt: epochMs | null,                       // pick·draw·reveal 단계의 끝 시각. 첫 정답으로 줄면 새 값
  rushed: bool,                                 // 첫 정답 뒤 30초로 줄어든 상태인가
  mask: '□□□' | null,                           // draw 동안. 글자마다 □, 띄어쓰기 자리는 공백. settings.len 이 false 면 null
  word: string | null,                          // ★ 그리는 사람(draw·reveal), 이미 맞힌 사람(draw), reveal 단계의 모두. 그 밖에는 null
  choices: [{ w, topic }, x3] | null,           // ★ 그리는 사람, pick 단계에서만
  canUndo: bool, canRedo: bool,                 // 그리는 사람에게만 뜻이 있다(나머지는 false)
  reveal: null | {                              // reveal 단계
    word, why: 'all'|'time'|'give'|'idle'|'skip'|'left',
    gains: [{ id, pts, order }],                // 맞힌 사람들, order 1 = 첫 정답
    drawerPts: number, guessers: number,        // 그린 사람 점수, 맞힐 수 있던 사람 수
    nextId: id | null },                        // 다음에 그릴 사람(마지막 문제면 null)
  ranking: null | [{ id, name, rank, score, correct }]   // final 단계. 나간 사람도 남는다
}
```

- ★ 표시가 "정답이 새지 않는다" 약속의 대상이다. `word`·`choices`를 다른 사람 상태에 넣지 않는다(`test/draw/leaks.test.js`).
- 프로필 사진은 상태에 넣지 않는다. 라이어게임과 같은 `faces` 알림으로 보낸다.
- 그림은 상태에 넣지 않는다(10-5).

## 11. 배포와 숨김 스위치

- 환경 변수 **`DRAW`**: `off`(기본. 화면·서버에 흔적 없음) / `test`(주소에 `?draw=1`이 있을 때만 로비 칸이 보임) / `on`(모두에게 보임).

## 12. 완성 확인 시나리오

1. **한 판 끝까지**: 3명이 `?draw=1` 주소로 들어와 방을 만들고(순서대로, 2라운드) 시작한다. 그리는 사람에게만 단어 3개가 뜨고, 고르면 나머지 화면에는 `□□□`만 보인다. 그린 선이 나머지 화면에 1초 안에 같은 모양으로 나타난다. 한 명이 맞히면 "○○ 님 정답!"이 뜨고 시간이 30초로 줄며, 나머지 한 명도 맞히면 바로 정답 공개. 빨리 맞힌 사람 점수가 더 높고 그린 사람도 점수를 받는다. 6문제가 끝나면 최종 순위가 뜨고 "한 판 더"로 다시 시작된다.
2. **정답이 새지 않는다**: 그리는 동안 못 맞힌 사람의 기기가 받은 모든 메시지에 단어가 없다(자동 시험). 먼저 맞힌 사람이 채팅에 정답이나 힌트를 써도 못 맞힌 사람 화면에는 보이지 않는다. 그리는 사람이 채팅·이모티콘·사운드를 누르면 "그림으로만 설명해 주세요"가 뜬다.
3. **끊김과 늦게 들어오기**: 그리는 도중 맞히는 사람이 새로 고침하면 지금까지의 그림이 그대로 다시 보인다. 진행 중에 새 사람이 들어오면 지금 그림을 보고 다음 문제부터 맞힐 수 있다. 그리는 사람이 15초 넘게 끊기면 정답이 공개되고 다음 사람으로 넘어간다.
4. **휴대폰 가로·iPad**: 844×390 화면에서 그림판·색 12개·도구가 겹치지 않고 다 눌린다. iPad에서 펜슬로 그릴 때 손바닥을 대도 선이 생기지 않고, 손가락으로 색을 바꿀 수 있다. 빠르게 원을 그려도 각이 지지 않는다. (실기기 확인 필요)
5. **출제 순서 세 가지**: "맞힌 사람"으로 하면 가장 먼저 맞힌 사람이 다음에 그리고, 한 라운드 안에서 같은 사람이 두 번 그리지 않는다. "랜덤"으로 하면 순서가 매번 다르지만 모두 한 번씩 그린 뒤에야 다음 라운드가 된다. 되돌리기를 세 번 누르고 다시 하기를 두 번 누르면 모든 사람 화면이 같은 그림이다.
6. **숨김 스위치**: `DRAW=off`면 로비와 서버 어디에도 갱식마인드가 없다. `test`면 `?draw=1` 주소에서만 칸이 보인다. 포커·블러핑·라이어는 전과 똑같이 돌아간다(`npm test` 통과).
